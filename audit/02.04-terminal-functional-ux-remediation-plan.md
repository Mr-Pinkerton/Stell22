## Approach: lot commit (F-03 + Cancel)

**Метод: pending lot until rails confirmed.**

Не коммитить `lotId` до `onConfirm` диалога реек с `v > 0`. Cancel только закрывает диалог и сбрасывает `pendingLotId`. Committed `lotId` / `railsTaken` / `picks` не меняются.

Тот же committed лот → диалог правки `railsTaken` (`initial` = текущее), Cancel оставляет прежнее число.

Грязный ввод + другой лот/партия → сначала диалог «Введённые данные будут сброшены.» Остаться / Сбросить и сменить.

- «Остаться»: state без изменений.
- «Сбросить и сменить» на **лоте не вайпит сразу**: открывает pending-rails. Если потом Cancel реек — старый ввод цел. Сброс picks — в `applyRailsConfirmed`, когда `pendingLotId !== committedLotId`.
- Партия: «Сбросить и сменить» = существующий `resetLot` + новый `batchId`.

Dirty: `railsTaken > 0 || pickedCount > 0`.

Blanks: `lotId != null && railsTaken > 0`.

После успеха TORCOVKA: clear rails/picks/ack; новый `clientRequestId` через `clearDraft`; refresh; оставить `batchId` если партия ещё в `data`; оставить `lotId` если лот есть и `remainingQuantity > 0` (из **refresh**). Иначе `lotId = null`. `railsTaken = 0` → секция заготовок скрыта, пока снова не введут рейки.

Не держать stale `remainingQuantity`.
