## What changed

P1-1. The one-shot container is no longer started from the mutable tag `stell22-p1-oneshot:node22`. The operator asks the local Docker daemon for `{{.Id}}` of that tag, then inspects that id again. Both values must be `sha256:` plus 64 lowercase hex digits and must be equal. Production accepts only the id in `/var/lib/stell22/p1-oneshot-image-pin.json` (`kind` = `PRODUCTION_ONESHOT_IMAGE_PIN`). The repository does not contain that file. Test-owned scope cannot read it. A test must pass `testApprovedOneShotImageId`, and a production request that carries that field stops with `INJECTED_PRODUCTION_DEPENDENCY`.

The approved id is part of the dossier canonical JSON, so the existing `dossierSha256` binds it. The signed payload keys are unchanged: `attemptId`, `daemonId`, `decision`, `dossierSha256`, `kind`, `nonce`, `notAfter`, `notBefore`, `operation`, `recoverySha256`, `scope`. The spawn argument is the digest, with `--pull never`. The tag is rejected if it appears in the argument list. The same observation is repeated after the plan is built and immediately before `authorize()`. A missing, malformed, unpinned, unapproved, or changed id stops with `spawned=false`, does not write the ambiguous-completion marker, and does not create the authorization replay marker.

P1-2. The public CLI prints one machine-readable line:

```text
verdict= code= phase= attempt= imageGitSha= oneShotImageId= dossierSha256= recoverySha256= recoveryEvidence= signingInputs= spawned= retryAttempted= targetClass=
```

`recoveryEvidence` is `NONE` or `VERIFIED`. `signingInputs` is `COMPLETE` only when the verdict is not `STOP` or `BLOCKED`, `recoveryEvidence` is `VERIFIED`, and both digests are 64-hex SHA-256. Otherwise a recovery hash is printed as `UNAVAILABLE`. A preflight dossier is `INCOMPLETE`. An early stop is `NOT_SIGNABLE`. The line does not contain the database password, `DATABASE_URL`, or a PostgreSQL URL.

The reviewed build recipe is `docker/p1-oneshot/Dockerfile`: `node:22-bookworm-slim` and `prisma@6.19.3`. It is not `:latest`. The operator does not build, pull, or retag the image. Building or installing that image on a production host is a separate authorization. This package does not perform it.

## Not in this package

P1-3 write-freeze is not implemented. The other Opus findings are not implemented: host-wide lock scope, crash-time secret handling, fingerprint parentheses, `lock_timeout`, restore runbook, and host runbook. P1 SQL, the historical migration inventory, SHADOW, ledger authority, and the production application are unchanged.

After the pre-spawn recheck, `authorize()` runs and then the container is created. A tag move cannot select a different image, because the argument is the digest. Deleting that digest in the interval after authorization and before the daemon creates the container can still consume the signature. That window is not closed by starting the container before authorization.
