## What this package is

The coordinator lives in `src/server/internal/p1-write-freeze-coordinator/`. Resource names use the prefix `stell22-p1wc-` and the label `stell22.p1.write-freeze-coordinator`. Business databases are only `p1wc_` plus 8 hex digits. Restore databases are only `p1wcr_` plus 8 hex digits, and a restore database cannot be the source. The image database `stell22` is the bootstrap database required by `postgres:17-alpine`. The coordinator refuses to freeze `stell22`.

Three disposable roles sit beside the bootstrap superuser `stell22`:

- `p1wc_breakglass` is a login superuser used only as the protected administrator.
- `p1wc_migrator` is login, not a superuser, and has no createdb, createrole, replication, or bypassrls. It owns the business database and the public objects.
- `p1wc_app` is the same class of non-superuser. It does not own the protected objects, does not inherit the migrator or the break-glass role, and cannot `SET ROLE` to the migrator after the freeze.

Passwords are generated for the cluster and redacted from command output. There is no production mode and no caller DSN.

`FROZEN_VERIFIED` means the application role has no effective business write, and no uncontrolled writer session was present at the check. Coverage is `APPLICATION_ROLE_ONLY`. Revoking application DML does not stop the bootstrap superuser, the break-glass superuser, or the owning migrator. An open session of either superuser blocks `FROZEN_VERIFIED` and records `UNCERTAIN`. The existence of the bootstrap role, with no open session, does not by itself block the freeze. Advisory locks, a maintenance flag, row counts, and `REVOKE` without draining existing sessions are not a freeze.

## State machine

`REVOKE_COMMITTED` is the design intermediate between a committed privilege transaction and the drain. It is not an extra product state.

Happy path: `NORMAL` → `FREEZE_REQUESTED` → `REVOKE_COMMITTED` → `DRAINING` → `FROZEN_VERIFIED` → `BACKUP_IN_PROGRESS` → `RESTORE_VERIFICATION` → `AWAITING_OWNER_AUTHORIZATION` → `P1_APPLY` → `P1_POSTCHECK` → `UNFREEZE_AUTHORIZED` → `NORMAL`.

Fail closed:

- A privilege rollback stays `FREEZE_REQUESTED`.
- A crash before the privilege commit stays `FREEZE_REQUESTED`.
- A crash after the commit and before the drain becomes `UNCERTAIN`.
- A crash during the drain becomes `UNCERTAIN`. `REREAD_FROZEN` can return to `FROZEN_VERIFIED` only when the application freeze, the grants, and the digest still match.
- Backup failure, restore failure, failed P1, and a failed postcheck become `BLOCKED`.
- An ambiguous P1, where the SQL committed and the journal did not record it, becomes `MANUAL_RECOVERY_REQUIRED`. The new column is left in place. The source is not restored.
- A missing or expired simulated approval stays `AWAITING_OWNER_AUTHORIZATION`. The nonce is not consumed and the window is not extended.
- `TIMEOUT` is a known event with no edge. It does not unfreeze.
- `BLOCKED` and `MANUAL_RECOVERY_REQUIRED` have no path to `NORMAL`.
- Identity drift after `NORMAL` appends `IDENTITY_UNREADABLE` and becomes `UNCERTAIN`.

The journal is append-only `journal.ndjson`, fsynced, under an exclusive lock. A torn tail with a valid prior entry forces `UNCERTAIN` unless the state is already `BLOCKED`, `UNCERTAIN`, or `MANUAL_RECOVERY_REQUIRED`. A lock already held returns `LOCK_HELD` and does not write.

## Freeze and unfreeze

The privilege change is one transaction. It revokes application and `PUBLIC` table DML, sequence mutation, schema and database `CREATE`, column write grants in `public`, and `EXECUTE` on security-definer functions in `public`. It grants the application `CONNECT`, schema `USAGE`, and `SELECT`. It does not set `NOLOGIN` and does not set `default_transaction_read_only`. Catalog privileges outside `public`, including `PUBLIC` update on `pg_catalog.pg_settings`, are not treated as business writes.

Existing application sessions are terminated after the commit. An open application transaction cannot commit its insert: the row is absent and the digest is unchanged. A new application connection then receives SQLSTATE `42501` for `INSERT`, `UPDATE`, `DELETE`, `TRUNCATE`, `nextval`, `setval`, `CREATE TABLE`, `SET ROLE p1wc_migrator`, and the security-definer function. `SELECT` still succeeds.

`pg_catalog` column privileges are excluded from the business-grant check. A remaining `PUBLIC` write grant in schema `public` refuses `FROZEN_VERIFIED`.

Unfreeze requires a separate test-owned approval, a passed postcheck, a non-ambiguous P1, the migrator as owner, the application role still non-superuser and without `CREATE`, and the same container id and `StartedAt`. It restores application DML and sequence use. It does not grant `CREATE`. If the post-grant write probe fails, the state becomes `UNCERTAIN` and does not return to `NORMAL`.

Approvals are a test-owned simulation. Scope must be `TEST_OWNED`. A field named `ownerSignature`, or any scope other than `TEST_OWNED`, is `FORGED_OWNER`. The maximum window is 15 minutes. A nonce is 32 hex characters and is consumed only when the transition succeeds. Replay of a consumed nonce fails. This package does not call the owner signer.

Pinned P1 is the existing migration file. The coordinator hashes the supplied SQL and refuses `P1_PIN_MISMATCH` before execution. The accepted hash is `47ff9c932aea0a692b81ecfaf6c4a931b431e3e332e3e9c5b3fca96694550fe5`, taken from `git show` bytes. The application role cannot run that DDL. The migration file is not modified.

The logical digest hashes explicit columns of the fixture tables and `BatchCreationCommand`. It excludes the P1 column and sequence `last_value`. Sequence `nextval` is not rolled back by PostgreSQL and is not used as rollback proof. `rejectDestructiveRestore` always returns `DESTRUCTIVE_RESTORE_FORBIDDEN` and does not restore the source.

## Residual limits

The freeze is application-role coverage plus a point-in-time session check. A superuser or the owning migrator can still write. A later privileged write changes the logical digest, and the backup or postcheck then stops, but the coordinator does not continuously hold every privileged session closed. Sequence values survive rollback. This unfreeze is test-owned and is not a production unfreeze. The coordinator is not called by the production operator, the production entrypoint, Compose, or `scripts/deploy.sh`.
