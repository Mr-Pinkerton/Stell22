## 1. CURRENT COMPONENT STRUCTURE

Экран собирается не в одном файле. Хедер, restore-черновика и тосты живут снаружи.

      OperationTileRow + OperationTile[]  все IN_WORK (+ текущий batchId)
    Section «Пакеты и рейки»            только если batchId
      OperationTileRow + OperationTile[] лоты партии
      Empty
    Section «Заготовки»                 только если lot найден

### 1.2 Batch selection

- Список: `data.batches` со `status === "IN_WORK"` **или** `id === batchId` (чтобы восстановленный черновик не потерял закрытую партию).
- Плитка: иконка `Boxes`, `title = b.name`, материал `materialById.get(b.materialId)?.name` + сечение `${width}×${height}`.
- Выбор: `selectBatch` → `setBatchId` + `resetLot()` (лот, railsTaken, picks, pendingAck сбрасываются).
- Все партии в одном горизонтальном ряду. Выбранная отличается `active` (`border-brand bg-brand/5 border-2`).
- Референс: **одна** выбранная карточка партии. Сейчас выбранная не отделена от списка.

### 1.3 Rail / lot selection

- Фильтр: `batchId` совпал и (`remainingQuantity > 0` **или** `id === lotId`) — снова для stale draft.
- Плитка: `Пакет {code}` или `Поштучно`; subtitle одной строкой `{length} · {сорт пакета} · {тип} · ост. {remainingQuantity}`.
- Выбранный лот: `highlight` «Взято {railsTaken} реек».
- Тап: тот же лот → открыть QuantityDialog реек; другой лот → сброс picks/rails/pendingAck и сразу диалог реек.

`TerminalRailLot` (`types.ts` + `serLot` в `terminal.ts`):

| Поле | В терминале | Смысл |
| --- | --- | --- |
| `id` | да | ключ |
| `batchId` | да | связь с секцией 1 |
| `code` | да | идентификатор пакета |
| `isPackage` | да | пакет vs поштучно |
| `lengthM` | да | длина рейки лота |
| `railType` | да | Полка / Канавка |
| `sort` | да | сорт **пакета** (вход), не сорт заготовки |
| `remainingQuantity` | да | текущий остаток на складе |
| `quantity` (schema) | **нет** | исходное кол-во. **Не показывать** |
| сечение / порода | нет на лоте | есть на выбранной партии |

### 1.4 Blank / quantity entry

- Длины **не вводятся вручную**. `lengthTiles` = уникальные `Detail.lengthM` с `status=ACTIVE` и `detailType === lot.railType`, сортировка по возрастанию.
- Сорт заготовки — вкладка `activeSort` (`SORT1` / `SORT2`). Это **факт выхода**, не сорт пакета. Из любого пакета можно нарезать оба сорта.
- Количество: тап плитки → `QuantityDialog`. Ключ строки `pickKey(lengthM, sort)` = `${lengthM}|${sort}`.
- `max` в диалоге длины: `maxDetailQuantity` (INV-008: суммарный выход ≤ `railsTaken × lot.lengthM`), только если `railsTaken > 0`. Если рейки ещё не введены, max не ставится (сабмит всё равно заблокирован при `railsTaken <= 0`).
- Редактирование: повторный тап, диалог с `initial = текущее qty`.
- Удаление: текстовая кнопка «Сбросить» на плитке (`onClear`). В QuantityDialog **нельзя** подтвердить 0 (`canConfirm = numeric > 0`). Это семантика диалога, её не менять.
- Сетка: `OperationTileGrid` = `grid-cols-5`. Плитка `h-40`.

### 1.5 Waste calculation (клиент, без смены формул)

`computeTorcovkaWasteMetrics(railsTaken, lot.lengthM, picks)`:

- `takenM = railsTaken × lengthM`
- `producedM = Σ(lengthM × quantity)`
- `wasteM = max(takenM − producedM, 0)`
- `wastePct = wasteM / takenM × 100`
- band: `< 20` NORMAL, `< 50` SUSPICIOUS, иначе EXTREME (`torcovka-plausibility.ts`)

`overLength` = `producedM > takenM` → Confirm disabled. Отдельной строки ошибки над баром **нет** (текст лимита есть только внутри QuantityDialog).

Confirm bar сейчас (если есть `wasteMetrics`):

| Строка | Единица |
| --- | --- |
| Фактически взято реек | `railsTaken` шт |
| Общая длина | `takenM` м (`formatLength`) |
| Получено заготовок | `pickedCount` шт |
| Полезный выход | `producedM` м |
| Отход | `wasteM` м **и** `wastePct` %; цвет `wasteBandClass` |

Если лот пропал, но ввод есть: «Черновик: {railsTaken} реек, {pickedCount} заг.»

### 1.6 Dialogs

| Диалог | Триггер | Семантика (не менять) |
| --- | --- | --- |
| QuantityDialog rails | выбор лота / повторный тап выбранного | `railsTaken`; hint «Не указывайте количество реек во всём пакете»; `max = max(remaining, railsTaken)` |
| QuantityDialog length | тап длины | qty по `lengthM+sort`; лимит длины реек |
| SUSPICIOUS | `pendingAck.band === "SUSPICIOUS"` | Отмена = `setPendingAck(null)`; Подтвердить = `retryWithAck("SUSPICIOUS")` с echo-метриками |
| APPROVAL_REQUIRED | `pendingAck.status === "APPROVAL_REQUIRED"` | 4 цифры, `allowLeadingZeros`; неверный/ротация → toast `CODE_ROTATED_MESSAGE`, код очищается |
| TerminalDraftResumeDialog | login / выбор другой операции | `TerminalApp`, не `TorcovkaScreen` |

### 1.7 Footer / actions

`TerminalConfirmBar`: sticky `bottom-4`, `surface-card`, summary слева `text-sm`, кнопка `variant="brand"` `h-14` «Подтвердить».

Сейчас бар **монтируется только если** есть `wasteMetrics` (лот + `railsTaken > 0`) **или** lotMissing-черновик с вводом. Референс и план 02.02: показывать pinned-бар уже при выбранном лоте (нули до ввода реек). Это презентация, не смена `disabled`.

Disabled: `railsTaken <= 0 \|\| pickedCount === 0 \|\| overLength \|\| submitting`.

**Не** disabled из-за `stockLow` / `lotMissing` (owner 01.12: stale stock = warning, возможен DI-007 replay).

Shared с присадкой и упаковкой. Менять дефолтный chrome бара глобально нельзя.

### 1.8 Loading / errors / draft restore

| Состояние | Где | UI |
| --- | --- | --- |
| Загрузка каталога | `TerminalApp` до `data` | «Загрузка данных…» |
| Submit in flight | `submitting` | кнопка disabled; диалоги ack тоже |
| Валидация / сеть / сервер | `toast.error` | текст `Error.message` |
| Успех (в т.ч. replay как CREATED) | toast.success + `clearDraft()` + `onDone()` | уход на home |
| lotMissing / stockLow | amber `<p>` над баром | не блокирует Confirm |
| F5 | cookie сессии + PIN заново → resume dialog | гидрация `useTerminalDraft` + `restorePendingAck` |
| Logout / idle 5 мин / login | тот же draft key `employeeId` | isolation по работнику |
| Пустой список лотов | `Empty` | «Нет доступных реек в партии» |
| Нет длин | `Empty` | «Нет длин для этого типа рейки» |

## 2. LOGIC vs PRESENTATION

Цель рефактора — трогать в основном **E**. A–D остаются в `TorcovkaScreen` (или в уже существующих lib/hooks).

### A. Business / state logic — не выносить

Держать в `TorcovkaScreen`:

- `batchId`, `lotId`, `railsTaken`, `picked`, `activeSort`
- `dialog`, `submitting`, `pendingAck`, `approvalCode`
- `selectBatch` / `selectLot` / `resetLot`
- `confirm` / `retryWithAck` / `retryWithApprovalCode`
- фильтры `batches` / `lots` / `lengthTiles` / `lotMissing` / `stockLow` / `overLength`
- `ackPhase` для черновика

Новый UI-флаг «список партий развёрнут» (если секция 1 сворачивается) — **только презентация**, в draft **не** писать.

### B. Draft persistence — не двигать

- `useTerminalDraft({ employeeId })` — один экземпляр на экран
- `clientRequestId` из хука, не `newRequestId()` на каждый submit
- `useEffect` autosave: `batchId, lotId, railsTaken, picks, activeSort, ackUi.phase, ackUi.approvalCode`
- `clearDraft()` только после серверного успеха
- `restorePendingAck({ draft, railLots })` как initializer `useState`

Файлы: `use-terminal-draft.ts`, `terminal-draft-storage.ts`, `restore-pending-ack.ts`. UI-проход их не меняет.

### C. Server interaction — не менять контракт

```ts
submitTorcovka({
  employeeId,
  clientRequestId,
  batchId,
  railLotId,
  railsTaken,
  picks,
  plausibilityAck?, // только retry SUSPICIOUS
  approvalCode?,    // только EXTREME
})
```

Публичные статусы, которые UI уже понимает: `CREATED` | `ACK_REQUIRED` | `APPROVAL_REQUIRED`. Replay выглядит как `CREATED`.

### D. Calculations — не дублировать и не менять

- `computeTorcovkaWasteMetrics`
- `maxDetailQuantity` / `formatLength`
- `wasteBandClass` можно оставить или перенести как чисто CSS-хелпер

### E. Visual rendering — зона UI-прохода

- разметка секций, карточки партии/лота/длины, табы, summary children, отступы, sticky vs pinned footer, размеры тапа
- существующие диалоги: **остаются смонтированными в родителе**, меняется только обёртка/классы при необходимости

## 4. VIEWPORT / RESPONSIVE

Отдельного terminal breakpoint / landscape media **нет**. Нет `viewport` meta кроме дефолта Next. Корень: `min-h-screen flex-col`. Home — `overflow-y-auto`; **торцовка — нет**: скролл документа, бар `sticky bottom-4`.

Фактическая цель: сенсорный киоск / планшет **landscape**, широкая сетка 5 колонок. Узкая ширина должна остаться терпимой (горизонтальный скролл лотов, сетка сжимается), не consumer-mobile redesign.

Рекомендуемый каркас торцовки (layout-only):

```text
main.flex.flex-1.min-h-0.flex-col
  scroll.flex-1.overflow-y-auto.scrollbar-thin-y   секции 1–3
  pinned summary                                   не зависит от прокрутки секций
```

Так Confirm всегда на экране, как в референсе. `sticky` внутри общего бара присадки/упаковки не трогать.

## 8. STATE OWNERSHIP / REFACTOR RISK

Не менять владельца состояния, пока нет доказанной нужды. Нужды нет.

| Состояние | Где жить | Если вынести презентацию |
| --- | --- | --- |
| draft + `clientRequestId` | `useTerminalDraft` в `TorcovkaScreen` | не создавать второй хук |
| pendingAck + approvalCode | родитель | диалоги остаются siblings секций |
| submitting | родитель | все кнопки Confirm/Ack читают его |
| picked / railsTaken | родитель | карточки получают props + callbacks |
| QuantityDialog open | `dialog` в родителе | не открывать диалог внутри карточки своим useState |

Риски UI-рефактора:

| Риск | Что сохранить |
| --- | --- |
| Draft persistence | тот же `saveDraft` effect, те же поля payload |
| request ID | один id на жизнь черновика; новый только в `clear()` |
| Approval dialogs | не размонтировать при скролле секций; `restorePendingAck` initializer |
| Double submit | `submitting` до await |
| F5 | гидрация из localStorage; phase approval только если уже был server APPROVAL_REQUIRED |
| Employee isolation | ключ storage = `employeeId`; экран получает `employee` от App |

Correction workflow (админское исправление операции после факта) на этом экране **не живёт**. Не трогать.
