## Audit trail

`writeChangeLog` stores `userId` only when the caller passes it (`src/server/change-log.ts:24–31`). These callers do not:

- `createEmployee` (`employees.ts:120–124`). The payload is `auditEmployee`, which omits the PIN and records `pinChanged` on update.
- `createMaterial` (`materials.ts:64`).
- `markEmployeePaid` (`payroll.ts:216–222`). That log is inside the payment transaction, so it commits with the payment, and it still has no actor.
- `setAccountConfirmed` (`finance.ts:416`). That log is written after the transaction returns. A crash between the commit and the log leaves the account change without a row.

On `p1iso_bcb1a393` the employee, material, and account-confirmation rows were written with `userId` null. The account row itself became `confirmed`. A crash between that commit and the log line was not staged. `BA-P09-002`. API credential saves log the field names only (`settings.ts:77–84`), which was already checked in phase 08. No secret was printed here.

Marketplace sync writes a system log with the admin id (`marketplace-sync.ts:535`). That path was not executed. `BA-P06-001` stays the demo-persist card.

## Background work

There is no in-process scheduler in the application service. The cost recalculation queue is the in-memory map in `src/server/cost-queue.ts`. A process exit drops a queued run. That remains `DI-012`. It was not re-run.

`POST /api/cron/fetch-statements` does not open mail when `MAIL_*` is empty and does not run when `CRON_SECRET` is empty. Those production values were not read. Host cron and the unpaid-VPS gap are outside this code. A missed backup while the machine is stopped is not a defect in `scripts/backup-db.sh`.

`scripts/run-mp-sync.ts` does not sync. It tells the operator to use the admin action.

## Backup and deploy, static only

`scripts/backup-db.sh` checks the `pg_dump` status itself, prints `BACKUP SUCCESS` only after those checks, and says that line is not a restore proof. Retention deletion stays off until a restore drill exists. A kill between the checksum and the archive can leave a checksum without an archive. The script was not executed. `docker-compose.prod.yml` health check is `GET /api/health` and is not a restart condition. Deploy workflows were not run.
