## Как Cursor ведёт чеклист

1. `[ ]` означает открыто, `[x]` — **исправлено, проверено и принято HEAD**. Написание кода, commit, push и даже зелёный CI сами по себе не являются закрытием.
2. Для каждой карточки после закрытия добавлять под ней: `**Закрыто:** PR #…, SHA …, тест/сценарий …, HEAD ACCEPT …, дата …`. Если решений Owner не хватает — оставлять открытой.
3. Один ID BA = ровно один чекбокс в разделах волн. Допускается один PR на несколько связанных карточек, но каждая закрывается по своему критерию.
4. Не изменять текст исходных карточек аудита и не закрывать исторические findings автоматически. `UNVERIFIED` сначала проверить, не выдавать предположение за воспроизведённый дефект.
5. После каждого утверждённого изменения обновлять **только этот постоянный файл**, не создавать новую версию чеклиста; вносить запись в журнал внизу.
6. Для денежных и складских изменений: тесты на disposable DB, защита истории, отдельно утверждённые миграции. Никогда не проверять рискованные сценарии записывающими действиями на production.

## Волна 4. Отчётность, цели и интерфейс

UTC+3 уже принят как бизнес-календарь. Даты зарплатной недели и семантика дублей целей требуют решения владельца.

- [ ] **BA-P03-001 · P3. При упаковке неприсаженных деталей показывается неправильная причина.**
  **Готово, когда:** Текст «Недостаточно остатка» не объясняет отсутствие готовых деталей.

- [ ] **BA-P04-001 · P3. Детализация зарплатного долга ограничена 31 днём.**
  **Готово, когда:** Платёж включает все дни, но развёрнутый список показывает только 31.

- [ ] **BA-P04-002 · P3. Неделя зарплаты скрывает смысл общей задолженности.**
  **Готово, когда:** Фильтр относится к истории выплат, а долг считается за всё время.

- [ ] **BA-P06-002 · P3. Продажи суммируются с ошибкой float.**
  **Готово, когда:** Сложение Decimal через Number даёт 18,009999999... вместо 18,01 ₽.

- [ ] **BA-P06-003 · P3. Продажи разных МП объединяются по одинаковому SKU.**
  **Готово, когда:** Одинаковый текст артикула у WB/Ozon может слить показатели разных изделий.

- [ ] **BA-P07-001 · P2. Дашборд использует UTC вместо бизнес-дня UTC+3.**
  **Готово, когда:** Операции первых трёх часов месяца попадают в предыдущий месяц.

- [ ] **BA-P07-002 · P3. График «Выручка» на самом деле показывает поступления.**
  **Готово, когда:** Денежные CashFlow ошибочно названы продажной выручкой.

- [ ] **BA-P07-003 · P3. График отходов обрезан 14 днями.**
  **Готово, когда:** Во второй половине месяца отходы не попадают на график.

- [ ] **BA-P07-004 · P3. Неделя зарплаты отличается от недели дашборда.**
  **Готово, когда:** Зарплата: пятница–четверг, дашборд: понедельник–воскресенье.

- [ ] **BA-P08-002 · P3. Дробная цель 0,4 превращается в план 0.**
  **Готово, когда:** Значение принимается, но округляется в ноль.

- [ ] **BA-P08-003 · P3. Минимальный остаток 0,4 превращается в 0.**
  **Готово, когда:** Нулевой порог фактически отключает предупреждение о дефиците.

- [ ] **BA-P08-004 · P3. Дашборд не предупреждает о дефиците изделий и деталей.**

- [ ] **BA-P08-007 · P2. Цель производства зависит от timezone сервера.**
  **Готово, когда:** Упаковка начала месяца может засчитаться в прошлом месяце.

- [ ] **BA-P10-001 · P3. Нижний пункт меню перекрыт при низком окне.**
