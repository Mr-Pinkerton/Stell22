## Failure-state model

`preflight` only reads. It does not take the host lock, the attempt lock, or create a credential directory.

`verify-recovery` and `apply` take one host-wide lock before any attempt directory is created, then the existing per-attempt `operator.lock`. The per-attempt `adapter.lock` inside apply stays. A second attempt id cannot pass the host lock by using another directory.

A lock file is evidence. The code does not delete a lock it does not own, does not treat a malformed lock as free, and does not steal a lock left by a dead process.

Spawn has a separate intent file, `sealed.production-adapter-spawn-intent`. It is written after the credential files exist and before `authorize()`. A rejected authorization removes that file before the refusal is returned. A crash after the file exists, including after the signature is consumed and before `spawn`, leaves the file. The next command returns `SPAWN_INTENT_UNCERTAIN` or `AMBIGUOUS_COMPLETION` and does not spawn. An uncertain state is never returned as `ALREADY_APPLIED`.

## Lock lifecycle

Production path: `/var/lib/stell22/p1-operator.host.lock`. Test-owned runs use `p1-operator.host.lock` inside the supplied work root.

The record is `kind=P1_OPERATOR_HOST_LOCK`, a 32-hex owner, the attempt id, and `verify-recovery` or `apply`. It is created with `wx` and `fsync`.

| Condition | Code | What the code does |
| --- | --- | --- |
| A complete record is already present | `HOST_LOCK_HELD` | Leave the file |
| The path is a symlink, directory, or incomplete record | `HOST_LOCK_UNCERTAIN` | Leave the path |
| The directory cannot be created or the file cannot be written | `HOST_LOCK_UNAVAILABLE` | Do not replace an existing record |
| Release sees a different owner | `HOST_LOCK_OWNER_MISMATCH` | Do not unlink |

Release unlinks only when the current record owner is the owner this run wrote.

## Intent-marker ordering

1. Read-only checks, restore evidence, and the per-attempt adapter lock.
2. Exclusive credential directory. An existing directory or symlink is `SECRET_DIRECTORY_COLLISION`. Nothing is deleted.
3. `sealed.production-adapter-spawn-intent` is written and `fsync`ed.
4. Authorization runs. A refusal removes the intent this attempt wrote, then returns that refusal. No ambiguous marker is written for that refusal.
5. Spawn. A throw, a signal, or a postcheck that cannot prove the migration writes the existing ambiguous marker and leaves the intent.
6. A proven `P1_APPLIED` result removes the intent this attempt wrote. Credential cleanup then runs. If cleanup cannot prove ownership, the result becomes `SECRET_CLEANUP_FAILED` and the foreign files stay.

## Credential cleanup

`p1-production-credentials` is created with `mkdir` that does not replace an existing path. `owner`, `database.env`, and `migrate.cjs` are `wx` files. Cleanup `lstat`s each path. It deletes a file only when the owner record matches and the path is a regular file. A symlink is not followed and is not unlinked. Diagnostic files that this run did not create stay in the directory.

## Manual recovery

These steps are for a human after a crash. The program will not perform them.

1. Do not start another `verify-recovery` or `apply` while `p1-operator.host.lock`, `operator.lock`, `sealed.production-adapter-spawn-intent`, or `sealed.production-adapter-ambiguous-stop` exists.
2. Confirm no operator process from that attempt is running. Confirm no disposable container or network labeled for that attempt is running. Do not remove a container whose id, name, or labels do not match that attempt.
3. Read `_prisma_migrations` and the P1 objects before deciding whether the migration finished. A missing marker is not proof that it did not run. A present intent is not proof that it did.
4. Only after that classification, the human may remove a stale host lock, an attempt lock, and a credential directory whose `owner` file names the dead run. Remove `database.env` in that same step so the password is not kept as diagnostic evidence. Keep the intent and ambiguous markers until the classification is written down outside this program.
5. Do not delete those markers in order to make the next attempt spawn.

Production crash recovery has not been tested. No production process was killed, and no production lock or credential file was inspected.

## R1 — file identity

HEAD review of the first crash-safety commit required another correction before merge. `releaseProductionCredential` treated a regular file at the expected path as owned when the owner file text matched. A different regular file at that path could be deleted. The owner token was the attempt id.

R1 records `dev` and `ino` from the file descriptor that created each credential file, the host lock, and the spawn intent. That descriptor stays open until the cleanup decision, so a replacement cannot reuse the inode number before the check. Cleanup unlinks only when the path still has that identity and, for the owner record, the invocation token still matches. The credential owner token is a random 32-hex value created for that invocation. A path whose contents match, but whose file identity does not, is left in place. A partial write or a close failure removes the partial file only when its creating identity still matches; otherwise the partial file stays and is not returned as an owned credential. None of these cleanups uses recursive deletion.

The last identity check and the unlink are still separate calls. A replacement in that interval is not closed by `fs.unlink` on a path. This correction does not claim that interval is impossible. A credential file left by SIGKILL is still a manual recovery item. Production crash recovery has not been tested. The per-attempt `operator.lock` in `operator.ts` and the disposable `postgres.env` cleanup still match owner text before `unlink`. They are outside this correction.
