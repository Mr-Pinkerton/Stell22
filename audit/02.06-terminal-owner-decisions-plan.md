## Decision 1 — HOURS without hourly rate: block UI and server

**Current:** `HoursScreen` already shows «Почасовая ставка не задана» when `hourlyRate` is null/0, but Confirm is only `hours <= 0`. `submitHours` accepts any `hours > 0` and writes `hourlyRateSnapshot: null` (DI-015 snapshot-as-is). UI `rate = employee.hourlyRate ?? 0` treats null as 0 for money preview.

**Invariant:** After `lockAndReadRateSnapshots`, if the snapshot is not a payable rate (`null` / `undefined` / `0` / negative / non-finite), reject with `Почасовая ставка не задана` before `ProductionOperation.create`. Helper: `isHourlyRateUnavailable` (Decimal-safe). Do not coerce an unavailable rate to 0 for write. Piece-rate snapshots unchanged. Idempotent replay of an existing `clientRequestId` still returns without creating a second row. UI matches: `rate == null || rate <= 0`.

**Server required:** YES (`submitHours`).

**Files:** `src/lib/hours-input.ts` (new), `src/lib/hours-input.test.ts` (new), `src/server/terminal.ts`, `src/components/terminal/hours-screen.tsx`, `src/server/terminal.security.test.ts`.

**Tests:** rate absent + 1h / 0.5h → throw, `productionOperation.create` not called.

## Decision 8 — UPAKOVKA why disabled

**Current:** Client `canAssemble` uses `detailsReady`, `nomenclature` stock, BOM `details` / `fastenerIds` / `packagingId` / `extraIds`. Tile `disabled={max===0 && qty===0}` swallows `onClick`. TerminalData has detail **names**, but nomenclature items are **ids only** — cannot factually say «Петля» without loading names.

**Invariant:** Same min-floor formula. Server serializes `{ canAssemble, shortages[] }` per product. Client does not invent a second formula. `canAssemble > 0` → quantity dialog, max from server. `canAssemble === 0` → tappable muted tile, info dialog, no quantity entry. Shortages = BOM lines that cannot supply one unit (`available < required`). Kinds: `detail` | `fastener` | `packaging` | `extra`. Names from Detail / NomenclatureItem. No warehouse writes.

**Server required:** YES (`getTerminalData` + shared helper). `submitUpakovka` already fails on insufficient stock; no formula change there.

**Files:** `src/lib/upakovka-availability.ts` (new), `src/lib/upakovka-availability.test.ts` (new), `src/components/terminal/types.ts`, `src/server/terminal.ts`, `src/components/terminal/upakovka-screen.tsx`, `src/components/terminal/operation-tile.tsx` (`allowClickWhenDisabled`), `src/server/terminal.security.test.ts` (DTO mock).

**Shape:**

```ts
stock.upakovka[productId] = {
  canAssemble: number,
  shortages: { name, kind, required, available, shortage }[]
}
```

`shortage = required - available` for the **summed** one-product requirement on that physical key.

**Parity:** `upakovkaAvailability` aggregates demand by physical stock key (`detailId` vs `nomenclatureId`) before `floor(available / totalRequired)`. Sequential `applyUpakovkaPrepared` decrements of the same id for quantity=1 are that sum, so `floor(stock / sum)` is the exact complete-product count that key can support. `canAssemble` is the min over keys. Display: one shortage line per key. `kind` from `NomenclatureItem.type` (FASTENER → fastener, PACKAGING → packaging, else extra) — display only.
