## What is implemented

`PRODUCTION_ROLE_NAME` stays `stell22`. Catalog reads, `pg_dump`, and the disposable restore still authenticate that target role. `TEST_ROLE_NAME` stays `p1pa`. The P1 one-shot is the only command that receives `stell22_migrator`.

The dossier digest now includes `migratorRole`. An authorization signed for an older digest does not match. The signed payload keys are unchanged: `attemptId`, `daemonId`, `decision`, `dossierSha256`, `kind`, `nonce`, `notAfter`, `notBefore`, `operation`, `recoverySha256`, `scope`.

Production reads `/var/lib/stell22/p1-migrator-credential.json` and no other path. The repository does not contain that file. The operator does not create it. A test-owned run reads `migrator-credential.json` under that attempt's directory, which is derived from the attempt root, not from a caller flag. The file must be a regular file, kind `P1_MIGRATOR_CREDENTIAL`, role exactly `stell22_migrator`, and database equal to the authenticated target database. On Linux the mode must have no group or other bits. A missing, empty, substituted, or mismatched file stops the apply. The bootstrap `POSTGRES_PASSWORD` is not accepted as the migrator password. The CLI still rejects `--database-url`.

Before authorization, the adapter connects over the Docker network as `stell22_migrator` with `scram-sha-256` and reads `pg_roles`, ownership, and grants. It reads that report twice. A change between the reads is `MIGRATOR_PRIVILEGE_DRIFT` and does not consume the approval. The accepted report requires `LOGIN`, `NOSUPERUSER`, `NOCREATEDB`, `NOCREATEROLE`, `NOREPLICATION`, `NOBYPASSRLS`, `NOINHERIT`, no role membership, ownership of `BatchCreationCommand`, `INSERT` and `UPDATE` on `_prisma_migrations`, `CREATE` on schema `public`, and no `CREATE` for `PUBLIC`. At least one other non-superuser login must exist, and none of those logins may have schema `CREATE` or membership in the migrator. An empty application-role set is `APPLICATION_ROLE_UNBOUND`. This package does not invent a production application role name.

A failed privilege or credential check leaves `spawned` false. An ambiguous one-shot result stays `AMBIGUOUS_COMPLETION` and is not retried.

## What was proven on disposable PostgreSQL 17

The live tests use `postgres:17-alpine` and random `p1pa-*` names. They do not connect to production. After the historical migrations and the recovery archive, the test creates `stell22_migrator` and `p1pa_app`, revokes `CREATE` from `PUBLIC`, and transfers ownership of `BatchCreationCommand` and `_prisma_migrations`. The bootstrap role remains the superuser used for catalog and backup.

On that cluster: a superuser migrator is refused before spawn; membership in the bootstrap role is refused; unexpected ownership is refused; a wrong password is refused by the database; `p1pa_app` cannot `ALTER` `BatchCreationCommand`; the migrator one-shot applies the pinned P1 bytes. The operator apply uses the same credential file and the same probe. Crash-safety unit tests still reach spawn only when the injected report is acceptable.

## Separate prerequisite

Package B showed that the historical entrypoint runs `npx prisma migrate deploy` with `DATABASE_URL` and can start when nothing is pending. This package does not change that image or grant DDL to the application role. Removing migration execution from the application entrypoint is a separate change. Until that change exists, a pending migration in the application image is expected to fail for a restricted application role.

## R1 security corrections

HEAD review `https://github.com/Mr-Pinkerton/Stell22/pull/100#issuecomment-6252317541` is **REWORK REQUIRED**. This section records the three corrections on the same branch. It does not replace the package C record above.

### Immutable probe image

The privilege client is `docker run` of the image id observed on the authenticated database container. `postgres:17-alpine` is inspected only as a consistency check. The tag id and a direct inspect of that digest must both equal the container image id. The password env file is created after that decision. A replaced tag, a missing image, a different digest, a different daemon, a different Docker endpoint, a different network, or a hostname other than `db` stops before `docker run`. The command does not publish a port and does not add `--privileged`, `--cap-add`, `--user`, or `--pid`. There is no fallback to the tag. Credentials are not passed to an image that failed those checks.

### Credential file

The production path remains `/var/lib/stell22/p1-migrator-credential.json`. This package does not create it. On Linux the reader walks every path component with `lstat`, refuses a symlink, refuses an other-writable ancestor, and requires the immediate parent to be owned by the reader without group write. The file must be a regular file of at most 4096 bytes, owned by the reader, with no group or other permission bits. It is opened with `O_RDONLY|O_NOFOLLOW`. `fstat` of that descriptor must match the path `dev`/`ino` before the read and again after it. The descriptor is closed on every path, including a failed read. The reader has no write and no delete. A platform without a proven `getuid` and non-zero `O_NOFOLLOW` fails with `MIGRATOR_CREDENTIAL_UNSUPPORTED` before any byte is read. That result is not a Linux-equivalent credential proof.

### Privilege report

`rolsuper`, `rolcreatedb`, `rolcreaterole`, `rolreplication`, `rolbypassrls`, `rolcanlogin`, `rolinherit`, `migrationInsert`, `migrationUpdate`, `schemaCreate`, and `publicCreate` must be boolean values present on the report. A missing `rolsuper` is not evidence of `NOSUPERUSER`. Each `otherLogin` entry must contain `name`, `schemaCreate`, `memberOfMigrator`, and `superuser` with those exact types. Memberships must be an array of strings. A missing field, a null, a wrong type, a malformed membership list, an incomplete login entry, or an unexpected key is `MIGRATOR_PRIVILEGE_REFUSED`. The accepted state is unchanged: `LOGIN`, `NOSUPERUSER`, `NOINHERIT`, no memberships, no privilege escalation, ownership of `BatchCreationCommand`, `INSERT` and `UPDATE` on `_prisma_migrations`, `CREATE` on schema `public`, and no `CREATE` for `PUBLIC`.

`otherLogin` is a catalog list of other non-superuser logins. It does not prove that the deployed application container authenticates as one of those logins. The deployed application role remains unverified. `stell22` remains the bootstrap target role.

The adapter still reads the catalog twice, before authorization and before the one-shot spawn. A difference is `MIGRATOR_PRIVILEGE_DRIFT` and does not consume the approval. Those two reads are not an atomic guarantee against a later role change.
