## 1. What this candidate is

The code under `src/server/internal/p1-isolated-runner/` builds a private migration directory from the pinned Git blobs and classifies Prisma history plus P1 catalog evidence supplied by the caller.

Two entry points stay separate:

- The public CLI, `scripts/p1-isolated-runner.ts`, plans by default. `apply --attestation` checks the JSON shape and then stops with `LIVE_DISPOSABLE_PROBE_NOT_IMPLEMENTED`. The current CLI does not connect to PostgreSQL and cannot spawn Prisma.
- The exported `executeDisposableApply` function can spawn `prisma migrate deploy` only when the caller injects `probeIdentity`, `readHistory`, `readSchema`, and `spawnPrisma`. Those callbacks are not an independent container inspection and they are not a database read.

There is no production flag, force flag, bypass flag, `migrate resolve` path, SQL replay, or retry after an ambiguous spawn. Real authentication and old-application integration require a separately authorized future package. This source is not proof of live disposable-target isolation.

## 2. Verdicts

| Verdict | Meaning in this candidate |
| --- | --- |
| `READY_FOR_DISPOSABLE_APPLY` | Forty-five historical rows match the pinned checksums and are finished. P1 has no history row. The P1 column, check, function, and trigger are absent. |
| `ALREADY_APPLIED` | P1's finished row matches the pinned checksum and the catalog evidence matches the structural contract in `schema-contract.ts`. Keyword presence is not enough. A repeat call does not spawn Prisma. |
| `STOP` | Inventory, checksum, identity, or object-definition mismatch. Also a non-zero Prisma exit. No retry. |
| `BLOCKED` | Failed, rolled-back, unfinished, partial, or ambiguous bookkeeping; host-lock contention; ambiguous process completion. No automatic recovery. |

Schema classification compares caller-supplied evidence with a structural contract: public schema and table, one column, one validated CHECK, one zero-argument plpgsql function, and one enabled trigger whose definition names `public."BatchCreationCommand"` and `public."batch_creation_command_provenance_guard"()`. The CHECK must be exactly SQL NULL or `jsonb_typeof(...) = 'object'`. The function body must match the P1 migration body after comment stripping and whitespace normalization. An unqualified name is rejected because it depends on `search_path`. The probe SQL uses `pg_namespace` joins and is not executed. Live `pg_get_*` formatting is **NOT VERIFIED**.

## 3. Disposable boundary

An attestation is declared JSON: UUID run id, database name `p1disp_<run id>`, loopback host, user `p1disp`, 64-character container id, service name tied to that run, image `postgres:17` or `postgres:17-alpine`, major version 17, and a nonce of at least 32 characters. Rejected names include `stell22`, `stell22_integrity`, and `stell22_dev`. Rejected container names include `stell22-db-prod`, `stell22-app`, and `stell22-caddy`. Host `db` is rejected. Localhost without the rest of the attestation is rejected.

The exported executor then calls the injected identity callback and compares that callback's result with the attestation. It does not inspect a container and it does not read a nonce from PostgreSQL. The live identity SQL is unimplemented. A callback that echoes the attestation satisfies the comparison. The public CLI never calls this function.

The child environment is an allowlist: `PATH`, `PATHEXT`, `SYSTEMROOT`, `WINDIR`, `TEMP`, `TMP`, `TMPDIR`, `HOME`, `USERPROFILE`, `HOMEDRIVE`, and `HOMEPATH`, matched without regard to case. A case collision on one of those keys drops it. `DATABASE_URL` is set from the attestation URL only. `NODE_OPTIONS`, `PRISMA_*`, `PG*`, `POSTGRES_*`, `PROD_*`, and case-variant connection keys are not copied. The parent environment is left unchanged. The CLI does not build this environment because it does not spawn Prisma.

The host lock is an exclusive file create on a caller-supplied path. This candidate does not take Prisma's session advisory lock. A stale lock is not deleted. The gap between the last hash check and the child start is not claimed to be atomic.

After a spawn has started, a launch failure, a signal, a non-zero exit, a post-spawn hash failure, or a throw from history, schema, or classification writes `.ambiguous-stop` when the sealed directory can accept it. That marker is not deleted. The process does not retry and does not call `migrate resolve`. If the marker cannot be written, the result is `AMBIGUOUS_COMPLETION_UNRECORDED`. That result does not claim a later call is blocked if the sealed directory is removed afterwards.
