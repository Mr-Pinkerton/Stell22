
## 3. Transaction gate-first order

Accepted SHADOW-capable marketplace persistence order:

```text
BEGIN TX

→ Supply global lock plan
→ validations
```

Outer gate snapshot `shadowWriteActive` is captured first and propagated into Supply accounting. Gateway may reacquire the same SHARED advisory xact lock later (reentrant).

Malformed `inventory_movement_shadow_write` fails closed before Sale, Supply, ProductStock, watermarks, MpStock, ChangeLog, and InventoryMovement. Remote API fetches before the DB transaction are not DB mutations.

## 4. Consume identity

Emitted only when an actual ProductStock decrement commits (`toRemove > 0`).

```text
stockDomain = PRODUCT
kind = CONSUMPTION
role = consume
quantityDelta = -toRemove
authority = SHADOW
epochId = NULL
causationKind = SUPPLY
causationId = Supply.id
reason = NULL
effectKey = imfx1:consume:<productTargetHashV1>:g=<generation>:w=<processedQtyAfter>
processedQtyAfter = newDeducted + newShortfall
stockAccountingGeneration = lifecycle.generation
```

Shortfall is never part of `quantityDelta`. Full shortfall (`toRemove = 0`, `shortfall > 0`) opens/updates the accounting cycle and emits **zero** InventoryMovement rows. A later quantity increase in the same generation uses the higher processed watermark and a distinct effectKey.

Retry / no-backfill: if `targetQty <= deductedQty + shortfallQty` there is no physical mutation and no movement. SHADOW OFF physical deduction followed by SHADOW ON retry of the same target must not backfill.

Consume causationSnapshot v1:

```text
{
  v: 1,
  d: "SUPPLY",
  type: "CONSUME",
  supplyId, marketplace, externalId, sku, productId,
  stockAccountingGeneration, processedQtyAfter,
  deductedQtyAfter, shortfallQtyAfter, quantityDelta
}
```

No money fields. No mutable Product name. No provider blob. No ChangeLog identity.

## 5. Restore identity

For an open cycle with `deductedQtyBeforeClose > 0` and retained `productId`:

```text
role = restore
kind = ADJUSTMENT
quantityDelta = +deductedQtyBeforeClose
causationKind = SUPPLY
causationId = Supply.id
effectKey = imfx1:restore:<productTargetHashV1>:g=<generation>:w=<deductedQtyBeforeClose>
```

Not `REVERSAL`. `reversalOfMovementId` remains NULL. Pre-SHADOW consume then ACTIVE restore is legal and does not require a historical consume movement.

Zero-restore (`deductedQty = 0`, `shortfallQty > 0`) still closes the cycle and emits **zero** movements.

Null-product positive restore remains `SUPPLY_CANCEL_PRODUCT_BINDING_REQUIRED` before ProductStock mutation, cycle close, movement, and ChangeLog.

Same-sync cancellation wins: no new consume for that snapshot; only the actual positive restore if prior `deductedQty > 0`.

Restore causationSnapshot v1:

```text
{
  v: 1,
  d: "SUPPLY",
  type: "RESTORE",
  supplyId, marketplace: "OZON", externalId, sku, productId,
  stockAccountingGeneration, deductedQtyBeforeClose,
  shortfallQtyBeforeClose, quantityDelta
}
```

## 6. effectiveAt

Supply `effectiveAt` is the server occurrence timestamp of the accounting physical mutation. Never marketplace `createdAt` / `acceptedAt` / provider time. `InventoryMovement.recordedAt` remains DB-generated. Separate Supply physical effects may have separate server occurrence timestamps. Persistence uses the common UTC-naive gateway contract.

## 7. Gateway invariant

For an outer SHADOW ACTIVE actual physical effect:

```text
result.gateActive === true
result.inserted === 1
```

Otherwise throw `SUPPLY_SHADOW_GATE_INVARIANT_VIOLATION` and roll back. Full shortfall / zero restore / retry/no-op do not call the gateway.

## 8. Cost-flow behavior

One TX-local `costFlowActive` remains pinned for global ProductStock planning + apply helpers.

- INACTIVE: quantity-only deduct/restore unchanged; SHADOW represents actual committed quantity changes.
- ACTIVE: missing ProductStock may be canonical initialized zero pool; full shortfall may still account; positive quantity-only deduct/restore fail `COST_FLOW_QTY_ONLY_WRITER`. No physical quantity effect → no movement.

No Inventory-style blanket dual-active error. `ARCH-P1-001` is untouched. Cost flow is not activated. Monetary Supply semantics are not implemented.
