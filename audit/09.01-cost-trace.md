## 3. C and waste

```
area = (widthMm/1000) × (heightMm/1000)
Vф   = producedLength × area
share by P×V, or by volume if P1 = P2 = 0
costSort2 = C − costSort1
₽/m³ = costSort / Vф
```

No output → zeros. `C` stays on `Batch.totalCost` and stays out of the wood blend.

Physical waste (`src/lib/waste.ts`) is metres: `max(0, taken − produced)` plus written-off remainder. It is not a money account. The whole `C` sits on produced metres, so kerf raises ₽/m. Uncut rails also hold none of `C` until they are cut (`COST-001`, still the live rule).

Accepted target BD-COST-06 / BD-COST-07 (consumed value stays on the rail; write-off is an explicit loss) is **not** what this report does. That target is behind the inactive gate. This is not a new defect of the live formula.

## 4. Labor and overhead

Payroll amount for an operation is `operationEarning` (`payroll.ts:232–261`): hours × hourly snapshot, pack qty × upakovka snapshot, torcovka qty × sort snapshot, prisadka qty × the flags on the line. Result rounded to kopecks with `Math.round`. Piece rates are snapshotted at submit (DI-015). Changing the employee card does not rewrite old operations.

SKU labor is not that sum. It is the period average rate times the **current** BOM (`COST-002`). Hours of a day are spread onto piece units of that employee-day. A day with only hours contributes nothing to the SKU (`payroll.ts:303–305`, `337–338`). There is no unit test for that hours-only branch.

Overhead is confirmed `EXPENSE` whose article category has `isOverhead` (`cost.ts:142–156`). The code does not exclude wage or delivery articles. A category flag can put the same delivery into `totalCost` and into overhead, or put production wages into overhead and into operations. That control gap is `COST-008` / BD-COST-04. Current code still allows it.

## 6. Physical sources of truth

While the cost-flow gate is off, stock quantities are `RailLot.remainingQuantity`, `BlankStock`, `DetailStock`, `ProductStock`, `NomenclatureStock`.

`InventoryMovement` (`schema.prisma` model at line 858) is quantity/provenance only, default authority `SHADOW`, no money columns. Its writer is a separate Setting, `inventory_movement_shadow_write`, and is not the cost gate. This phase did not read production rows. The cost report does not read `InventoryMovement`.

## 7. Dormant contour (code present, not the report)

When `isCostFlowActive` is true, the same transactions call the active writers:

- raw receipt / late ΔC / write-off: `cost-flow-raw.ts`, `finance-operations.ts:205–264` (`PURCHASE_VARIANCE` on `CostEvent`);
- TORCOVKA: `applyActiveTorcovkaInTx`;
- PRISADKA / UPAKOVKA / nomenclature pools: `cost-flow-downstream.ts`, `cost-flow-pools.ts`;
- inventory: `applyActiveInventoryConduct`;
- marketplace quantity writers throw if the gate is on (`supply-deduct.ts`).

`wacConsume` (`cost-foundation.ts:223–269`) moves components in proportion and gives the last unit the residual. That conservation rule is **not** the live report.

Active UPAKOVKA quantity edit throws `QUANTITY_EDIT_UPAKOVKA_COST_FLOW_NOT_READY` before the stock edit (`production-quantity-edit-tx.ts:262–265`). `ARCH-P1-001` stays **OPEN**. The throw stops the unfinished active edit. It does not implement it, and it does not authorize turning the gate on.

No bootstrap, no `CostPeriod` writer, and no report cutover were found. `03.02` already said that. This phase did not activate the gate and did not replay the active writers on a database.
