## 2. Causation contracts

`audit/08.19` §8 is the later accepted refinement where it differs from the historical `08.11` §2 Batch-id wording.

### createBatch

```text
causationKind = BATCH
causationId   = BatchCreationCommand.id
effectiveAt   = BatchCreationCommand.recordedAt
reason        = null
```

One `RECEIPT` / role `receipt` / `quantityDelta = +RailLot.quantity` per newly created RailLot with positive quantity. Target `RAIL_LOT / RailLot.id`. Exact key `imfx1:receipt:<railLotTargetHashV1>`. No qualifier. Zero quantity emits no movement. Negative quantity fails closed.

Causation snapshot v1:

```json
{
  "v": 1,
  "d": "BATCH",
  "type": "CREATE",
  "commandId": "...",
  "requestId": "...",
  "batchId": "...",
  "railLots": [{ "railLotId": "...", "quantity": 1 }]
}
```

`railLots` sorted by `railLotId`. No money/value fields. Do not copy `BatchCreationCommand.requestSnapshot`.

### writeOffBatchRemainder

```text
causationKind = BATCH
causationId   = BatchRemainderWriteOff.id
effectiveAt   = BatchRemainderWriteOff.recordedAt
reason        = null
```

Each retained effect: role `writeoff`, kind `ADJUSTMENT`, `quantityDelta` = retained negative, target `RAIL_LOT / railLotId`. Exact key `imfx1:writeoff:<railLotTargetHashV1>`. Movements come from the retained pre-mutation snapshot, not from rereading zeroed stock.

Causation snapshot v1:

```json
{
  "v": 1,
  "d": "BATCH",
  "type": "REMAINDER_WRITEOFF",
  "commandId": "...",
  "requestId": "...",
  "batchId": "...",
  "totalQuantity": 6,
  "effects": [{ "railLotId": "...", "quantityBefore": 6, "quantityDelta": -6 }]
}
```

Effects stay sorted by `railLotId`. No money fields.

Replay of request A after a later legitimate reopen must return success without inspecting restored stock and without a second movement. A new request B may write a second `BatchRemainderWriteOff` and a second causation; the same RailLot may reuse the semantic `writeoff` effectKey because `causationId` differs.

## 3. Common transaction order

All three physical transactions:

```text
requireAdmin OUTSIDE TX
↓
build retained USER actor OUTSIDE TX
↓
pure request validation / canonical request snapshot
↓
BEGIN TX
↓
SHARED SHADOW advisory lock + gate read
  isInventoryMovementShadowWriteActiveForWriter(tx)
↓
request-id advisory lock
↓
retained command lookup / replay handling
↓
business + stock locks / mutable validation
↓
derive exact physical effects
↓
physical projection
↓
retained causal identity where applicable
↓
SHADOW movement insert if captured gate ACTIVE
↓
status / ChangeLog
↓
COMMIT
```

Actor: `actorKind=USER`, `userId` = authenticated admin `User.id`, `actorDisplaySnapshot` = immutable admin display name. Retained `adminUserId` must match before movement insert. Fail closed on mismatch.

Outer captured `shadowWriteActive=false`: existing projection only; zero InventoryMovement rows; no helper call required beyond the early return. Outer `true`: physical projection and SHADOW insert are atomic in the same TX. Gateway result must be `gateActive=true` and `inserted=expected nonzero effect count`, else `RAW_PURCHASE_SHADOW_GATE_INVARIANT_VIOLATION` rolls back the TX.

Malformed/unsupported SHADOW Setting fails before the purchase request lock, business/stock locks, physical mutation, retained command, and ChangeLog.
