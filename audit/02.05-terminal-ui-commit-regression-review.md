## 3. Per-commit review

### 3.1 `06e9e273` — `fix(terminal): enable native touch scrolling in dialogs`

**Intent (commit body):** vertical overflow снят с transformed `DialogContent` и перенесён во внутренний native `pan-y` контейнер.

`DialogContent` (`src/components/ui/dialog.tsx`, не менялся) — `fixed top-1/2 left-1/2 -translate-x-1/2 -translate-y-1/2`. Overflow на этом узле плохо дружит с touch-scroll. Это и есть целевой баг EXTREME-диалога (до коммита на `DialogContent` уже стояли `max-h-[min(90vh,40rem)] overflow-y-auto scrollbar-thin-y`).

#### A. Presentation-only?

**No.** Есть CSS/разметка, но также:

- новый `max-h` на диалогах, у которых его не было;
- `touch-pan-y` на контейнере, внутри которого живёт keypad;
- dev-only `useEffect` probe.

Handlers submit/login/draft **не** менялись.

#### B. Behavioral surface

| Surface | Changed? |
| --- | --- |
| handler / hook / state init / `useEffect` (product) | NO (кроме dev probe) |
| navigation / login / session / submit / disabled / prerequisite / error / success | NO |
| draft persist semantics (`useTerminalDraft`, `terminal-app`) | NO |
| dialog **lifecycle** (`open` / `onOpenChange` / mount-reset QuantityDialog body) | NO |
| dialog **layout / overflow / touch-action** | YES |
| scroll/touch interception | YES (`touch-pan-y` on inner body; no pointer listeners) |
| keypad `onClick` / `press()` | NO (keypad file untouched) |
| keypad **hit-testing vs pan** | YES indirectly (parent `touch-pan-y`) |

Dev-only: `TerminalDialogScrollBody` вешает `window.__terminalTouchScrollProbe` при `NODE_ENV === "development"`. В production effect no-op.

#### C. Shared component?

YES. `QuantityDialog` — TORCOVKA + PRISADKA + UPAKOVKA. Новые `terminalDialogShellClass` / `TerminalDialogScrollBody` — Quantity, DraftResume, TORCOVKA SUSPICIOUS, TORCOVKA EXTREME.

#### D. Removed/replaced wrappers with behavioral meaning?

Не удалял рабочие pointer-handlers. **Добавил** inner wrapper. EXTREME: снял `overflow-y-auto` с transformed shell (это как раз смысл фикса). Quantity/Draft/SUSPICIOUS: **надел** shell+scroll туда, где overflow раньше не было.

#### E. Unintended semantics while fixing visual/touch UX?

**Likely for QuantityDialog.** Коммит чинил touch-scroll на transformed overflow. QuantityDialog до коммита **не имел** `overflow-y-auto` и `max-h`. После — общий cap `max-h-[min(90vh,40rem)]` = **640px при 16px rem**. Live overlay (без этого cap) измерил QuantityDialog **688×512**, top 56 / bottom 744 на 1280×800 — в вьюпорт **влезает**. Значит committed cap **создаёт** внутренний скролл (~48px) вокруг keypad+Confirm, которого на 1280×800 не требовалось.

Комментарий в `scroll-classes.ts` прямо признаёт риск:

> `touch-pan-y` пересекается с UA `manipulation` на button → свайп с кнопки может стать pan-y.

NumericKeypad — native `<button>`, не shadcn `Button`. `touch-action` live overlay: `auto`. Parent `touch-pan-y` на HEAD всё равно задаёт pan на скролле.

`cn()` = `twMerge`: `flex` из shell побеждает `grid` из `DialogContent`. Конфликт display с большой вероятностью снят. Не CONFIRMED clip, но inner scroll на Quantity — новый.

Close/confirm callbacks, `disabled={!canConfirm}`, `onOpenChange` → close: **unchanged**.

   **Severity: P3** тот же класс. Здесь обёртка **намеренная** (диалог длинный). Overlay **сохраняет** её.

### EXPECTED UI CHANGE

- EXTREME: overflow с transformed `DialogContent` во внутренний native scroll.
- Ширина Quantity/Draft 26/28rem → 32rem.
- Утилита `scrollbar-touch-y` (широкий thumb).

- DraftResume / SUSPICIOUS: обёртка без активации скролла на коротком контенте.

См. §8. Главное: Quantity + Draft + SUSPICIOUS теряют committed scroll wrappers; EXTREME не теряет. PIN contract и post-save navigation — overlay, не history.

## 10. Remediation recommendations

Не делать в этом этапе. Когда owner скажет «ок»:

1. **Не откатывать EXTREME inner scroll** — это единственный диалог, у которого overflow на transformed shell был до `06e9e273`.
2. **Quantity/Draft/SUSPICIOUS:** либо явно оставить overlay-модель (`terminalDialogContentClass` без inner pan-y), либо оставить HEAD-shell, но **не класть NumericKeypad в `touch-pan-y`** (скроллить шапку/метрики, keypad+футер `flex-none` снаружи). Второй вариант снимает P3 pan-vs-tap.
3. Если мержить overlay PIN: одним коммитом `terminal.ts` + `login-screen.tsx` + security tests. Не разносить throw/result.
4. Overlay post-save stay-on-screen / success ack — отдельное UX-решение (см. 02.03/02.04), не регрессия `06e9e273`.
5. Перед объявлением HEAD «touch-fixed» — live на **чистом** HEAD (stash overlay) Quantity + EXTREME пальцем: скролл, тап цифры, Confirm на 1280×800. Этот аудит это не делал.
