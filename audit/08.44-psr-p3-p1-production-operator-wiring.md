## What this package does

`src/server/internal/p1-production-adapter/operator.ts` builds the adapter dependencies from the resolved local Docker endpoint at execution time. The public CLI always uses scope `PRODUCTION`. It does not accept a callback, a caller `TargetFacts` object, a catalog snapshot, a `DATABASE_URL`, or a path to an approval file.

Test-owned calls may pass a work directory, a test-only public key, a signed document, a Docker environment, a spawn stand-in, or a lock-owner stand-in. The same fields on a production request stop with `INJECTED_PRODUCTION_DEPENDENCY`.

The runtime re-inspects the app container, the database container, the daemon id, and the catalog on each command. Container ids and image ids are Docker identities. `imageGitSha` stays `UNVERIFIED`.

Observed production names used as the contract, not as a substitute for that re-inspect, are network `stell22_default`, DNS alias `db`, PostgreSQL 17, database `stell22`, and role `stell22`.

## Operator boundaries

Same attempt id, 16 hex characters, on every command. `--attempt` is required. A missing prerequisite stops that command. A later command is not started by an earlier one.

| Command | Boundary |
| --- | --- |
| `preflight --attempt <id>` | Read-only inspect and catalog classification. No backup, no restore container, no Prisma. |
| `verify-recovery --attempt <id>` | Separate authorization to create this attempt's gzip backup, checksum, and witness, then restore into `p1pa-restore-<id>` on a different network. The source database is not the restore target. |
| `apply --attempt <id>` | Uses the persisted backup. Production also requires the daemon pin, the trust public key, and the installed signed approval. One pinned P1 migrate. No second spawn after an ambiguous completion. |

Exit 0 is only `PREFLIGHT_ONLY`, `RECOVERY_VERIFIED`, or `ALREADY_APPLIED`. `STOP` and `BLOCKED` exit 2. `preflight` and `verify-recovery` print `NO_APPLY`.

Production stops before Docker when GitHub Actions is set, when the pin file is missing or not a daemon id, and, for apply, when the installed approval file is missing. Test-owned scope is not the public CLI.

The database password is read from `POSTGRES_PASSWORD` on the source container and is not printed. The one-shot still receives it only through the mode `0600` credential file from the accepted planner.

## Recovery and ambiguous completion

`verify-recovery` writes `backup.sql.gz`, `backup.sql.gz.sha256`, and `backup.witness.json` under the attempt directory. An existing triple is not replaced.

Apply restores that archive into the disposable database again, then spawns one `prisma migrate deploy` of the pinned historical set plus P1. The application container is not rebuilt.

If the spawn status is null, the process is signaled, or the postcheck cannot prove 46 successful rows, the adapter writes `sealed.production-adapter-ambiguous-stop` beside the sealed directory and returns `BLOCKED` / `AMBIGUOUS_COMPLETION`. `retryAttempted` is false. A later call sees the marker and does not spawn. This package does not delete the marker and does not retry the migrate.

Manual intervention after that marker:

1. Leave the marker in place.
2. Read `_prisma_migrations` and the P1 column, CHECK, function, and trigger. Do not infer success from the process exit alone.
3. If P1 is absent and the row is unfinished or missing, the database needs a human decision before another attempt. A used signature cannot be replayed.
4. Remove the marker only after that decision. The software will not remove it.

## Remaining production prerequisites

1. A separate owner decision to authorize production P1.
2. The daemon pin at `/var/lib/stell22/p1-production-daemon-pin.json`, matching the live daemon id at execution time.
3. The owner Ed25519 public key at `/var/lib/stell22/p1-owner-authorization.pub`. The private key stays outside this repository, the executor, and CI.
4. An installed signed approval at `/var/lib/stell22/p1-owner-authorization.json` for the live dossier and recovery digests, plus the replay directory.
5. `verify-recovery` for that attempt on the production host, after the pin exists. The 2026-10-15 drill is not that backup.
6. Image git SHA remains `UNVERIFIED` until a real revision label or equivalent exists. The image id is not that SHA.
