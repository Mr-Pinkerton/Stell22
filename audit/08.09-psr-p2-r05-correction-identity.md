## 1. Why decrease-only lock is not idempotency

`correctTorcovkaRailsTaken` already locked `ProductionOperation` `FOR UPDATE` and rejected `newRailsTaken >= current`. That prevents some double RailLot increments **after success**, but:

- a retry after commit-unknown **errored** instead of returning the same correction;
- each success minted a new `ChangeLog.id` (cuid, unseen by the caller);
- concurrent different targets with the same expected-old were not CAS-protected as distinct commands.

R-05 adds a retained command identity and expected-old compare-and-set.

---

## 2. Accepted model — `ProductionOperationCorrection`

Narrow retained entity for **this** physical path only.

It is **not** generic Correction Center, **not** cancellation, **not** an InventoryMovement writer.

Logical command:

```
ADMIN requests: operationId, expectedOldRailsTaken, newRailsTaken, reason, requestId
```

Meaning: correct this TORCOVKA **from expected old X to target Y**. Not a blind “set current to Y”.

`requestId` is caller-supplied, globally UNIQUE, reused unchanged for retries of the **same** logical command. It is **not** `ProductionOperation.clientRequestId`. Format/validation reuses `requireClientRequestId` (trim, 1–128).

No Prisma relations / SQL `REFERENCES`. Scalar retained IDs (`operationId`, `adminUserId`, `railLotId`, `batchId`) so correction history cannot cascade-delete with another domain row.

---

## 3. Idempotent replay and stale CAS

Inside one DB transaction:

1. Acquire R-05 requestId advisory xact lock  
   `pg_advisory_xact_lock(8325, hashtext(requestId))`.  
   Namespace `R05_CORRECTION_REQUEST_LOCK_NAMESPACE = 8325` is **not** R-10 `(8322, 1)`. The lock is transaction-scoped concurrency only; hash collisions may extra-serialize unrelated requests and must not change correctness.
2. Lookup by `requestId`.
3. If found: payload must match `operationId`, `adminUserId`, `expectedOldRailsTaken`, `newRailsTaken`, canonical trimmed `reason`. Match → **SUCCESS** `replayed=true`, no stock/op/ChangeLog writes (even if the op is now paid/frozen). Mismatch → `REQUEST_ID_REUSE`. No physical row locks required for a committed correction.
4. If missing: lock `ProductionOperation` `FOR UPDATE`; re-check `requestId` against non-conforming writers.
5. Verify TORCOVKA and lot/batch/rails fields; reject paid.
6. Stale if `op.railsTaken !== expectedOldRailsTaken` → `STALE_CORRECTION` (do not reinterpret against the new current value).
7. Lock RailLot / Batch in the existing canonical order; reject frozen; length guard; inventory boundary.
8. Insert correction row (stable `id` = future `causationId`) **before** the physical RailLot/op write (and before the active cost-flow helper if that gate is on).
9. Apply existing physical effect; ChangeLog; optional batch reopen; commit.

Global `requestId` is serialized **before** correction creation, so cross-operation reuse of the same key is deterministic (`REQUEST_ID_REUSE`) and cannot leak a P2002 / aborted-transaction error among conforming writers. Existing op `FOR UPDATE` still provides operation CAS serialization for distinct requestIds.

Concurrent identical `requestId`+payload: one physical effect, one row, one primary ChangeLog; waiters replay.

Concurrent different commands both `expectedOld=10`: lock winner commits; loser is **STALE**, not a silent 8→6.

Sequential 10→8 then 8→6 requires a **new** `requestId` and `expectedOld=8`.

Do **not** recover UNIQUE violations with a SELECT in the same PostgreSQL transaction after P2002; that transaction is already aborted.

## 4.1 Exact schema / constraints

Prisma model `ProductionOperationCorrection` (no relations):

| Field | Type / notes |
| --- | --- |
| `id` | `String` `@id` `@default(cuid())` |
| `requestId` | `String` `@unique` |
| `operationId` | `String` (scalar; no FK) |
| `adminUserId` | `String` (scalar; no FK) |
| `railLotId` | `String` (scalar; no FK) |
| `batchId` | `String` (scalar; no FK) |
| `expectedOldRailsTaken` | `Int` |
| `newRailsTaken` | `Int` |
| `deltaReturned` | `Int` |
| `reason` | `String` |
| `recordedAt` | `DateTime` `@default(now())` `@db.Timestamptz(3)` |

**FK choice:** no Prisma relations and no SQL `REFERENCES`. Scalar retained IDs so correction history cannot be cascade-deleted with another domain row.

Migration: `prisma/migrations/20260918120000_psr_p2_r05_production_operation_correction/migration.sql`

Constraints / indexes:

- PK `id`
- UNIQUE `requestId`
- INDEX `(operationId, recordedAt)`
- CHECK `char_length(btrim(requestId)) BETWEEN 1 AND 128`
- CHECK `expectedOldRailsTaken > 0`
- CHECK `newRailsTaken > 0`
- CHECK `expectedOldRailsTaken > newRailsTaken`
- CHECK `deltaReturned > 0`
- CHECK `deltaReturned = expectedOldRailsTaken - newRailsTaken`
- CHECK `btrim(reason) <> ''`
- `recordedAt TIMESTAMPTZ(3) NOT NULL DEFAULT CURRENT_TIMESTAMP`

Empty table. No INSERT. No InventoryMovement changes.
