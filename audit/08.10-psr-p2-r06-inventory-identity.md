## 1. Reconnaissance evidence (why identity had to change first)

Pre-R-06 `createInventoryDraft` derived DETAIL lines from catalog Details / `getWarehouseStock().details`. No-prisadka Details alias the **full** shared `BlankStock` pool (`buildStockSnapshot`). Two ACTIVE catalog Details A/B with the same physical spec `(materialId, lengthM, detailType, sort)` produced two DETAIL lines, each with `accountedQty = pool quantity`.

Inactive conduct SET the shared pool per line (last write wins). Active `applyBlankInventoryLine` summed deviations through Detail.id. UI showed catalog names. Live validation compared each alias to the same pool (10 vs 10 twice). Inventory boundary expanded a spec to all no-prisadka Detail ids.

That identity cannot be dual-written: one physical pool would mint two InventoryMovement effects or two CostEvents.

R-06 closes identity **before** any INVENTORY InventoryMovement writer.

## 2. Accepted physical target model

Inventory counts **physically countable targets**.

| Line | Identity | Grain |
| --- | --- | --- |
| PRODUCT | `InventoryLine.refType=PRODUCT`, `refId=productId` | `ProductStock(productId)` |
| NOMENCLATURE | `refType=NOMENCLATURE`, `refId=nomenclatureId` | `NomenclatureStock(nomenclatureId)` |
| BLANK | `refType=BLANK`, `refId=BlankStock.id` | one `BlankStock` pool `(materialId, lengthM, detailType, sort)` |
| DETAIL | `refType=DETAIL`, `refId=detail.id` | ready aggregate of one **prisadka** catalog Detail |

A no-prisadka catalog Detail is **not** a physical inventory target.

Database `InventoryLine.refType` remains `String`. Application `InventoryRefType` is `BLANK \| DETAIL \| PRODUCT \| NOMENCLATURE`.

## 3. First-class BLANK InventoryLine

New drafts:

- All active no-prisadka Details that resolve to the same physical spec map to **exactly one** BlankStock pool and **exactly one** BLANK line (`refId = BlankStock.id`).
- A and B sharing `(M, 1.2, POLKA, SORT1)` → one BLANK line, not two DETAIL lines.
- Prisadka Details remain one DETAIL line (ready aggregate). WIP buckets are not exposed.
- PRODUCT / NOMENCLATURE unchanged.

`includeAllActive=true` still allows counting a physical blank pool from zero. For each unique spec referenced by active no-prisadka Details, draft creation **transactionally** ensures one `BlankStock` row (`quantity=0` if missing). Unique key `(materialId, lengthM, detailType, sort)` remains authoritative. No duplicate rows for A/B.

`includeAllActive=false` includes only currently countable/nonzero targets, with shared specs still deduped to one BLANK line.

Coverage boundary is **not** full physical reconciliation (not PSR-MUST-008):

- PRODUCT / NOMENCLATURE included
- BLANK = pools represented by active no-prisadka Detail specs
- READY DETAIL included
- WIP / partial DetailStock **not** added
- RailLot **not** added

## 5. DETAIL ready aggregate + deterministic bucket effects

Worker counts READY quantity for a prisadka Detail as one aggregate.

Physical projection (accepted):

- Canonical ready bucket `(detailId, torcevayaDone=detail.prisadkaTorcevaya, ploskostDone=detail.prisadkaPloskost)` → `afterQty = InventoryLine.actualQty`
- Every other existing READY bucket for that Detail → `afterQty = 0`
- Non-ready / WIP buckets **unchanged**

Example: torcevaya required; READY `(true,false)=4`, `(true,true)=3`; WIP `(false,false)=2`; accounted=7 actual=5 → `(true,false)=5`, `(true,true)=0`, WIP=2. Effects: canon `+1`, other ready `-3`. Aggregate delta `-2`.

Inactive conduct applies this derived target state. `normalizeReadyBuckets` remains the equivalent write plan; effect-plan tests and projection writes agree.

Active dormant branch (`applyDetailInventoryLine`) **always** consolidates other READY quantity/value into the canon pool first — including when aggregate `deviation === 0` (internal reclassification; no `INVENTORY_GAIN` / `INVENTORY_LOSS`). Net deviation is applied only after that canonicalization. **Physical quantity results match** the effect plan. Gate stays INACTIVE.

## 6. Derived physical effect plan

Internal/pure `InventoryPhysicalEffect` (`src/server/internal/inventory-physical-effects.ts`):

- `inventoryLineId`, `stockDomain`, `physicalTarget`, `beforeQty`, `afterQty`, `quantityDelta`
- **Not** a DB model, **not** InventoryMovement, **not** a retained event table

Physical target grains:

- BLANK `(materialId, lengthM, detailType, sort)`
- DETAIL `(detailId, torcevayaDone, ploskostDone)`
- PRODUCT `productId`
- NOMENCLATURE `nomenclatureId`

Within one Inventory document the plan contains each physical target **at most once**. Duplicate derivation fails closed (`DUPLICATE_INVENTORY_PHYSICAL_TARGET`). No silent summing of ambiguous independent count lines.

Zero-delta effects may remain in the internal plan. Future movements omit zero delta.

Line iteration order cannot change final physical state for the same locked pre-state + same document.

## 9. Live snapshot, locking, boundary, ChangeLog, unit cost

- `liveQtyForLine` for `BLANK` resolves `BlankStock.id` directly. Shared A/B is one comparison.
- BLANK locking locks **exactly** the referenced BlankStock pool, spec-sorted. Catalog aliases are not extra locks.
- Lock order documented in `lockInventoryStockRows`: Details (DETAIL lines) → BlankStock spec-sorted → NomenclatureStock → ProductStock. Inventory `FOR UPDATE` remains first. One global DRAFT. One DB transaction. Concurrent conduct: one wins / other `ALREADY_CONDUCTED`. Stale snapshot: `STALE_SNAPSHOT`, no projection mutation, no status flip, no conduct ChangeLog.
- `blankSpecToInventoryRefs` now returns the BLANK pool id **and** legacy no-prisadka DETAIL ids so DI-009 pool-aware boundary still covers both new BLANK lines and historical DETAIL aliases of that spec.
- ChangeLog remains audit only. BLANK conduct entries include `blankStockId`, `materialId`, `lengthM`, `detailType`, `sort`, `before`, `after`, `delta`. DETAIL retains aggregate line audit.
- BLANK unit cost = blended material ₽/м × length + `blankWorkCost(sort)` — physical spec/sort, not whichever Detail is iterated first. Preserves current `deviationSum` semantics. Does **not** activate monetary cost flow.

Active `applyBlankInventoryLine` applies **one** deviation to `BlankStock.id`. A/B aliases cannot mint two CostEvents. Gate not activated.
