## What the server checks

Every exported function in an `src/server/*.ts` file marked `"use server"` calls `requireAdmin()` or `requireTerminalEmployee()` in its opening, except the four public entry points: `signIn`, `signOut`, `terminalLoginByPin`, `terminalLogout`. That scan is the authorization matrix. Layout and `src/proxy.ts` are not the write boundary. The proxy only redirects a missing admin cookie and does not match `/api`.

A terminal token does not open an admin session, and an admin token does not open a terminal session. Checked with a disposable `SESSION_SECRET` in this process: `terminalAsAdmin` false, `adminAsTerminal` false, admin role `ADMIN`. `requireAdmin` then loads `User.role` from the database, so the role claim inside the token is not the grant.

## API password dialog

`/settings` loads `getApiCredentials()` in the server component and passes the values into the client tab (`src/app/(admin)/settings/page.tsx:8–18`). The tab keeps them in state while `unlocked` is false (`settings-api-tab.tsx:23–26`). The password action only flips that boolean. `saveApiCredentials` does not call it either. An admin session that opens the page has already been given the keys. `BA-P09-001`. This is not `SEC-002`: the unauthenticated export was moved behind `requireAdmin`. No live key was read.

## PIN and terminal

A second active row with that PIN, inserted directly, was accepted. `resolvePinLookup` then returned `collision`. Login itself was not called.

`createEmployee` with only a terminal cookie, and with no cookie, redirected to `/login` and wrote no employee. `getEmployeeEntries` for another id was rejected. After `archiveEmployee`, the same terminal cookie was rejected. Rates on a submit were read, not replayed.
