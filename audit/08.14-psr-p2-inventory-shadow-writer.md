## 2. Transaction order

```text
requireAdmin outside TX
→ retained USER actor
BEGIN TX
→ isInventoryMovementShadowWriteActiveForWriter(tx)
   SHARED advisory TX lock + gate read
→ read production_cost_flow
→ SHADOW ACTIVE + cost-flow ACTIVE → INVENTORY_DUAL_ACTIVE_UNSUPPORTED
  before business/stock mutation
→ Inventory FOR UPDATE
→ DRAFT / legacy checks
→ deterministic stock locks
→ STALE_SNAPSHOT
→ deriveInventoryPhysicalEffects
→ conductedAt = one server Date
→ existing projection mutation
→ if SHADOW ACTIVE: appendShadowInventoryMovements(...)
→ InventoryLine / status / ChangeLog
→ COMMIT
```

The SHARED advisory lock is held until COMMIT. The common gateway may acquire/read the writer gate again; the outer TX already holds SHARED so the gate cannot change underneath the physical action.

## 3. SHADOW safety decision

| Gate state | Behavior |
| --- | --- |
| SHADOW missing/inactive + cost-flow inactive | Existing projection. Movements **0**. |
| SHADOW missing/inactive + cost-flow active | Existing ACTIVE cost-flow behavior. Movements **0**. |
| SHADOW ACTIVE + cost-flow inactive | Projection + SHADOW movements atomically |
| SHADOW ACTIVE + cost-flow ACTIVE | Fail `INVENTORY_DUAL_ACTIVE_UNSUPPORTED` before mutation |

`INVENTORY_SHADOW_WRITER_NOT_CONNECTED` is removed.

## 6. Atomicity and retry

Movement insert is after projection mutation and before status/audit, same TX. Gateway failure rolls back projection.

Retry / COMMIT-UNKNOWN: DRAFT→CONDUCTED is the contour gate. Second conduct is `ALREADY_CONDUCTED`. UNIQUE(causationKind, causationId, effectKey) is not projection idempotency; the rollback test uses it only as an injected failure barrier.
