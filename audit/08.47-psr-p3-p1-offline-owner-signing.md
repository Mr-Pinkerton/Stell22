## Input

The Owner transcribes the `verify-recovery` result into a JSON object. The utility rejects a copied `verdict=` line. The object is labeled `UNTRUSTED_OPERATOR_EVIDENCE` / `OWNER_SUPPLIED` / `independentlyVerified: false`. Required fields are `scope=PRODUCTION`, `verdict=RECOVERY_VERIFIED`, `recoveryEvidence=VERIFIED`, `signingInputs=COMPLETE`, a 16-hex attempt id, a daemon id, two SHA-256 digests, and an image id `sha256:` plus 64 hex. `UNAVAILABLE` is rejected. The utility does not fill a missing digest.

The daemon id is printed by the operator only after the Docker session and the inspected runtime report the same id. A command that stops before that session prints `daemonId=UNAVAILABLE`.

The Owner must type the attempt id. `--yes`, `--force`, and a passphrase argument or environment variable are rejected. The utility does not connect to production, Docker, or a database, and it does not treat the supplied JSON as independent proof.

## Signed output

The file is `{ "payload", "signature" }` only. The payload keys match the verifier: `kind=OWNER_SIGNED_AUTHORIZATION`, `operation=P1_ONLY_APPLY`, `decision=AUTHORIZE_P1_ONLY_APPLY`, `scope=PRODUCTION`, plus `attemptId`, `daemonId`, `dossierSha256`, `recoverySha256`, a random 32-hex `nonce`, `notBefore`, and `notAfter`. The signature is Ed25519 over `canonicalJson(payload)`. The validity window is 15 minutes, inside the verifier's 24-hour maximum. The file is created with `wx` and mode `0600`. An existing path is left unchanged.

## Private key

The key path is an explicit argument. The utility does not search for a key. In production mode the only accepted private-key path is the explicit file `%USERPROFILE%\.stell22-owner-keys\owner-ed25519.pkcs8.pem` (the path the local generator R1 writes). Any other private-key path is `KEY_PATH_REJECTED` and is not opened. A signed approval is still refused inside that directory and under `/var/lib/stell22`.

The file must be a regular file, not a symlink. Its parent must be a real directory whose resolved path matches the path that was named; a junction or directory symlink is `KEY_UNAVAILABLE` or `KEY_PATH_REJECTED` and is not followed. The utility opens the file and requires the opened identity to match the listed identity before reading. It does not copy or move the private key and does not change the generator's files.

On Windows the key directory and the key file must each have exactly one non-inherited Allow FullControl entry for the current user SID. On Linux the directory and the file must have no group or world permission bits. If the ACL cannot be read, the result is `ACL_UNVERIFIED`. A readable but broader ACL is `KEY_PERMISSIONS_REJECTED`. The new approval file is created with `wx`, never overwrites an existing path, and receives the same single-user restriction after it is written. A partial write or a close failure removes only that new file while its identity still matches. A foreign file is left unchanged.

The accepted PEM is encrypted PKCS#8 (`BEGIN ENCRYPTED PRIVATE KEY`), including the generator's PBES2 form (PBKDF2-HMAC-SHA256, 600000 iterations, 16-byte salt, AES-256-CBC). An unencrypted key or a non-Ed25519 key is rejected. The passphrase is read as bytes from a hidden interactive prompt. It is not a command argument or an environment variable, and it is not written to the approval file or the status line. The entry buffer is wiped on success, on Ctrl+C, and on a setup failure, and the buffer passed into signing is wiped on every return path. Node's crypto and the JavaScript engine can retain copies that this process cannot wipe. This record does not claim guaranteed memory erasure.

The signature window remains 15 minutes. The verifier accepts the instant `notAfter` and refuses one millisecond later. Production apply runs the disposable restore before signature verification. A restore that consumes the rest of the window fails closed. The window was not extended.

## Trust boundary

Supplied evidence is untrusted. The signature proves that the Owner key signed those bytes. It does not prove that production matched them. Installing the public key and the approval on the production host is a separate authorization. This utility refuses `/var/lib/stell22` as a key or output path.
