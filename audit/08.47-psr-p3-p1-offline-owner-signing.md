## Input

The Owner transcribes the `verify-recovery` result into a JSON object. The utility rejects a copied `verdict=` line. The object is labeled `UNTRUSTED_OPERATOR_EVIDENCE` / `OWNER_SUPPLIED` / `independentlyVerified: false`. Required fields are `scope=PRODUCTION`, `verdict=RECOVERY_VERIFIED`, `recoveryEvidence=VERIFIED`, `signingInputs=COMPLETE`, a 16-hex attempt id, a daemon id, two SHA-256 digests, and an image id `sha256:` plus 64 hex. `UNAVAILABLE` is rejected. The utility does not fill a missing digest.

The daemon id is printed by the operator only after the Docker session and the inspected runtime report the same id. A command that stops before that session prints `daemonId=UNAVAILABLE`.

The Owner must type the attempt id. `--yes`, `--force`, and a passphrase argument or environment variable are rejected. The utility does not connect to production, Docker, or a database, and it does not treat the supplied JSON as independent proof.

## Signed output

The file is `{ "payload", "signature" }` only. The payload keys match the verifier: `kind=OWNER_SIGNED_AUTHORIZATION`, `operation=P1_ONLY_APPLY`, `decision=AUTHORIZE_P1_ONLY_APPLY`, `scope=PRODUCTION`, plus `attemptId`, `daemonId`, `dossierSha256`, `recoverySha256`, a random 32-hex `nonce`, `notBefore`, and `notAfter`. The signature is Ed25519 over `canonicalJson(payload)`. The validity window is 15 minutes, inside the verifier's 24-hour maximum. The file is created with `wx` and mode `0600`. An existing path is left unchanged.

## Private key

The key path is an explicit argument. The utility does not search `%USERPROFILE%\.stell22-owner-keys` and refuses that directory before opening it. It accepts only an encrypted PKCS#8 PEM (`BEGIN ENCRYPTED PRIVATE KEY`), the format Node reads and the format the local R1 generator writes. An unencrypted key or a non-Ed25519 key is rejected. The passphrase is read from a hidden interactive prompt and is not a command or environment parameter. The passphrase buffer is wiped. The private key and passphrase are not written to the repository, the approval file, or the status line.

## Trust boundary

Supplied evidence is untrusted. The signature proves that the Owner key signed those bytes. It does not prove that production matched them. Installing the public key and the approval on the production host is a separate authorization. This utility refuses `/var/lib/stell22` as a key or output path.
