## 2. Модель Server Actions (Next.js 16)

| Утверждение | Факт |
| ----------- | ---- |
| `"use server"` export | Публичная server-facing поверхность; **не** «только для внутреннего import» |
| Вызов с клиента | Client Component импортирует → POST с `Next-Action` header |
| Прямой POST | Возможен без UI, если action зарегистрирован в prod manifest |
| Tree-shaking | Неиспользуемые actions **могут** отсутствовать в prod build |
| Secure / action ID | **Не** является авторизацией |
| `proxy.ts` / middleware | Выполняется на том же pipeline, что и Server Action POST **на страницы** (matcher не исключает actions) |
| `(admin)/layout` `requireAdmin()` | Только RSC render; **не** выполняется на POST action (A22, `session.ts` L39–44) |

## 4. Слои авторизации

### 4.1 `proxy.ts`

```text
PUBLIC_PATHS = ["/login", "/terminal"]
matcher исключает: api, _next/static, _next/image, favicon, icon, sitemap, robots
```

- Проверяет только **admin** cookie `stell22_session` (подпись JWT, **без** проверки `role`)
- `/terminal` — **полностью публичен** (нет ни admin, ни terminal cookie gate на уровне proxy)
- `/api/*` — **не** проходит через proxy

### 4.2 `(admin)/layout.tsx`

- `requireAdmin()` на каждый RSC render admin-страниц
- **Не** защищает Server Action POST

### 4.3 Внутри actions

| Guard | Где вызывается | Экспортов |
| ----- | -------------- | --------- |
| `requireAdmin()` | `settings.ts` (6 fn), `marketplace.syncMarketplaces` | **8** |
| `requireTerminalEmployee()` | `terminal.ts` submit* + `getEmployeeEntries` | **5** |
| auth-flow (signIn/signOut/PIN) | `auth.ts`, `terminal.ts` login/logout | **4** |
| **нет** | все остальные admin read/write | **108** |

`session.ts`, `db.ts`, `change-log.ts`, `system-log.ts`, `cost-queue.ts`, `statement-mail.ts` — **не** `"use server"` (не client-callable surface).

## 5. Два класса reachability

### 5.1 Класс A — terminal worker (78 actions)

POST на **`/terminal`** проходит proxy **без** admin-сессии.

**Мутации без auth в теле (46):**

```text
cost: recalcBatchCosts, maybeFreezeBatch, archiveBatchIfDepleted
finance: createAccount, updateAccount, setAccountConfirmed, setAccountPrimary, deleteAccount,
  createCounterparty, updateCounterparty, deleteCounterparty,
  createArticleCategory, updateArticleCategory, deleteArticleCategory,
  createArticle, updateArticle, deleteArticle,
  createAutoRule, updateAutoRule, deleteAutoRule, reapplyAutoRules,
  createCashFlow, createTransfer, assignCashFlow, deleteCashFlow,
  convertCashFlowToTransfer, unlinkTransfer,
  createDeal, updateDeal, setDealStatus, deleteDeal,
  createStatement, importStatement, deleteStatement
goals: createGoal
notifications: notifyEvent, markNotificationRead, markAllNotificationsRead
payroll: markEmployeePaid
purchases: createBatch, updateBatch, deleteBatch, createSimplePurchase
settings: loadStoredApiCredentials
terminal: reversePrisadkaLine, reverseUpakovkaOperation
```

**Чтения без auth с terminal worker (21+):** `getTerminalData`, `getFinanceData`, `getDashboardData`, `getSalaryReport`, `getCostReport`, `getPurchasesData`, … (полный список — таблица §13).

**Blast radius (класс A):** финансы (ДДС, выписки, счета), закупки/партии, выплата ЗП, пересчёт себестоимости, API-ключи Ozon/WB, уведомления — **без единой cookie**.

### 5.2 Класс B — только admin workers (47 actions)

Примеры: `employees.createEmployee`, `nomenclature.createProduct`, `warehouse.conductInventory`, `production.deleteProductionOperation`, `marketplace.syncMarketplacesAsUser`.

POST на `/employees`, `/nomenclature`, … **без** admin cookie → `proxy` **redirect `/login`** → action, по модели Next.js, **не** должен выполниться.

**Оговорка:** при **валидной** admin JWT (любой пользователь из `User`, сейчас только роль ADMIN) proxy пропускает; внутри action `requireAdmin` **нет** — достаточно украденной/утёкшей session cookie.

## 10. Proxy × layout × Server Action POST

```text
Browser POST /terminal  + Next-Action: <id>
    → proxy: pathname public → NextResponse.next()  [NO admin cookie check]
    → (admin) layout NOT run
    → action body runs (no requireAdmin)
    → prisma mutations

Browser POST /employees + Next-Action: <id>  (no cookie)
    → proxy: redirect /login
    → action should NOT execute (Next.js middleware/proxy before action)
```

Admin cookie **не** проверяет роль (единственная роль ADMIN в enum). Terminal cookie **не** проверяется proxy.

## 14. Input validation (краткая карта)

**Zod нет.** Валидация — ручные `throw new Error` + Prisma constraints.

| Область | Паттерн | Пример |
| ------- | ------- | ------ |
| Finance mutations | positive amount, entity exists by name | `createCashFlow` L810–820 |
| Terminal submit | stock non-negative, batch/lot match, idempotency key | `terminal.ts` submitTorcovka |
| Purchases | volume math, deal sync | `purchases.ts` |
| Employees | PIN format, unique constraints | `employees.ts` |
| Settings save | requireAdmin + field list | `settings.ts` |

**Auth не заменяет validation:** даже с корректной validation, без auth attacker может вызывать mutations класса A.

## 15. Почему admin actions на terminal worker

Shared server graph: `dashboard.ts` импортирует `getFinanceData`, `getSalaryReport`, `getPurchasesData`, `getAppSettings`; client bundles на admin pages и `/terminal` тянут один server-reference chunk. Next регистрирует workers для **всех** страниц, где action может быть вызван (в т.ч. transitively). Это **не** смягчает риск — наоборот, публичный `/terminal` становится универсальной точкой POST для 78 actions.
