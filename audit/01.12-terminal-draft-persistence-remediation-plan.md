# Этап 01.12: Terminal draft persistence — remediation plan

> **For agentic workers:** do not implement until the owner says implement. When implementing: `superpowers:subagent-driven-development` or `executing-plans`. Evidence: `audit/01.11-terminal-draft-persistence-review.md`.

**Goal:** Unfinished terminal input of an Employee survives logout, idle lock, refresh, and browser restart on that kiosk, without creating server-side operation drafts or stock effects.

**Architecture:** localStorage per `employeeId`, schema `version: 1`, one active draft per employee. Screens autosave through one hook. Resume prompt after PIN. `clientRequestId` is owned by the draft, not regenerated on remount. Final submit still hits current server validation. Clear only on confirmed success or explicit delete.

**Tech Stack:** Next.js client components, existing `newRequestId()`, Vitest node + in-memory `Storage` mock. No Zod (not in the project). No Prisma migration.

**HEAD this plan assumes:** `16015d5ece9af8514a0ec3dc9c0fb913c15ced48`

### Owner update (2026-09-05, after DI-007/008 CLOSED in production)

- **IDLE timeout = 5 minutes** (`IDLE_MS = 5 * 60 * 1000`). Sliding kiosk-lock
  (pointerdown / keydown / pointermove) unchanged. JWT lifetime / cookie
  auto-login / terminal auth **not** redesigned.
- **Stale current-stock mismatch** is a **warning**, not an unconditional
  client-side Confirm block. Same `clientRequestId` may be an idempotent
  replay of an already committed submit (DI-007). Server remains source of
  truth. Hard-block only structurally impossible payloads (malformed draft /
  missing fields / `producedM > takenM`). On server validation error: keep
  draft.

This owner update **supersedes** D-8, Task 3, §4, §10 and the spec-review
row that froze `IDLE_MS` at 30 s, and **supersedes** any §6 wording that
would disable Confirm solely because current client-side stock is lower
than the saved draft (idempotent replay may already exist).

## Global Constraints

- Do not implement until the owner says implement.
- **No** schema / migration / server ProductionOperation draft rows.
- **No** PIN, JWT, admin secret, API keys in Storage.
- **No** change to `IDLE_MS` unless the owner separately answers YES to the timeout question.
- **No** DI-007 / DI-008 / reservation / inventory / payroll / cost work.
- Draft must not create Op, decrement stock, mutate Batch, wage, ChangeLog, or hold `FOR UPDATE` beyond the existing submit TX.
- `clientRequestId` created once per draft; reused after logout/reload; new id only after successful clear or explicit delete + new meaningful input.
- Auto-delete by age is forbidden.
- App code in this audit pass was not changed; this file is the spec for a later implementation.

### Locked design (from 01.11 + owner intent)

| ID | Decision |
| --- | --- |
| **D-1** | Storage = **localStorage**. Not sessionStorage, IndexedDB, or server drafts. |
| **D-2** | Key = `stell22:terminal:draft:<employeeId>`. One JSON object. |
| **D-3** | **One active draft per Employee** (TORCOVKA \| PRISADKA \| UPAKOVKA \| HOURS). |
| **D-4** | Isolation: read/write/clear only the session employee's key. Parsed `employeeId` must match session. |
| **D-5** | Clear only: server-confirmed success (including A21 duplicate-as-success) **or** explicit «Удалить черновик». |

| **D-7** | Stale entity: restore UI, do not wipe fields, do not auto-submit; server validates on confirm. |
| **D-8** | Idle 30 s stays until a separate owner decision. |

## 2. Types and parser

Put types next to storage so screens import one module.

```ts
export const TERMINAL_DRAFT_VERSION = 1 as const;
export const TERMINAL_DRAFT_KEY_PREFIX = "stell22:terminal:draft:";

export type TerminalDraftOperation = "TORCOVKA" | "PRISADKA" | "UPAKOVKA" | "HOURS";

export type TorcovkaAckUiPhase = "none" | "suspicious" | "extreme";

export interface TorcovkaDraftPayload {
  batchId: string | null;
  lotId: string | null;
  railsTaken: number;
  picks: { lengthM: number; sort: "SORT1" | "SORT2"; quantity: number }[];
  activeSort: "SORT1" | "SORT2";
  ackUi: {
    phase: TorcovkaAckUiPhase;
    highWasteReason:
      | "CURVATURE"
      | "CRACKS"
      | "KNOTS"
      | "MATERIAL_DEFECT"
      | "COLOR_TEXTURE"
      | "WRONG_SIZE"
      | "OTHER"
      | null;
    highWasteNote: string;
  };
}

export interface PrisadkaDraftPayload {
  picks: { detailId: string; kind: "torcev" | "plosk"; quantity: number }[];
}

export interface UpakovkaDraftPayload {
  picks: { productId: string; quantity: number }[];
}

export interface HoursDraftPayload {
  hoursInput: string;
}

export type TerminalDraftPayload =
  | { operationType: "TORCOVKA"; payload: TorcovkaDraftPayload }
  | { operationType: "PRISADKA"; payload: PrisadkaDraftPayload }
  | { operationType: "UPAKOVKA"; payload: UpakovkaDraftPayload }
  | { operationType: "HOURS"; payload: HoursDraftPayload };

export type TerminalDraftV1 = {
  version: 1;
  employeeId: string;
  clientRequestId: string;
  createdAt: string;
  updatedAt: string;
} & TerminalDraftPayload;

export type DraftParseFailReason = "malformed" | "unsupported_version";

export type DraftParseResult =
  | { ok: true; draft: TerminalDraftV1 }
  | { ok: false; reason: DraftParseFailReason };
```

Parser rules (no `JSON.parse` in UI without this wrapper):

1. `readDraft` catches `getItem` throws → treat as no draft.
2. `raw == null` / `""` → no draft.
3. `JSON.parse` in try/catch; failure → `{ ok: false, reason: "malformed" }`.
4. Require `typeof object`, not array.
5. `version === 1` else `unsupported_version`.
6. `employeeId`, `clientRequestId`, `createdAt`, `updatedAt` non-empty strings.
7. `operationType` ∈ enum; payload matches that type.
8. Integers: `railsTaken` / quantities ≥ 0, finite, `Number.isInteger`.
9. `lengthM` finite number > 0.
10. Reject extra secret-looking persistence only by **not writing** them. Extra unknown keys in JSON: ignore (forward compatible), do not copy to memory as PIN/token.

```ts
export function draftStorageKey(employeeId: string): string {
  return `${TERMINAL_DRAFT_KEY_PREFIX}${employeeId}`;
}
```

`writeDraft(storage, draft)`: `JSON.stringify` + `setItem` in try/catch; swallow quota / security errors; never throw into React.

`clearDraft(storage, employeeId)`: `removeItem` that key only.

`isMeaningful(draft): boolean` — 01.11 §8.

Inject `Storage` (`localStorage` in browser, mock in tests) so node vitest works.

## 3. Hook

`useTerminalDraft({ employeeId, storage? })`.

`storage` default: `typeof window !== "undefined" ? window.localStorage : undefined`. If undefined (SSR) — no-op read empty.

Returns:

```ts
{
  draft: TerminalDraftV1 | null;
  parseError: DraftParseFailReason | null;
  clientRequestId: string;
  save: (next: Omit<TerminalDraftV1, "version" | "employeeId" | "clientRequestId" | "createdAt" | "updatedAt"> & { payload: ... } | helper) => void;
  saveNow: () => void; // flush debounce
  clear: () => void;
}
```

Implementer may use a narrower `replacePayload(operationType, payload)` that preserves id/createdAt.

Behavior:

- On mount: `readDraft(employeeId)`. If ok and ids match → hydrate, **`clientRequestId = draft.clientRequestId`**. If empty → `clientRequestId = newRequestId()` held in ref, **not** written until first meaningful save.
- If parse fail: `draft=null`, `parseError` set, id still fresh in ref (unused until they start a new flow after delete).
- `save(payload)`: if not meaningful → if a draft exists and user emptied the form, **keep** draft until explicit delete or success (do not wipe by going to zero picks accidentally mid-edit). Exception: HOURS back to empty before first write — nothing to keep. Practical rule: once `createdAt` exists, updates may store empty picks (user cleared tiles) **without** deleting the row; resume still shows the flow. Simpler alternative that matches 01.11: empty meaningful-check on write **skips write** but does not clear. Prefer **skip write, do not clear** so a debounce of transient empty does not destroy the draft.
- Debounce 300 ms for `save`. Selection handlers call `saveNow()` after setState (use `useEffect` on the serializable snapshot, not per-render write).
- Effect: when `batchId/lotId/picks/hours/ack phase` change → schedule save. Discrete fields: `flush` immediately via deps without waiting if the change is a selection (lot/product/detail/batch). Acceptable implementation: one effect on a serialized snapshot + 300 ms debounce; selections are single setState so 300 ms is fine. Immediate save is a preference, not a second code path required if debounce is ≤ 300 ms.
- Unmount: `saveNow()` so Back/home still persists.
- Logout unmount: same flush. Then `TerminalApp` nulls employee; storage already has the JSON.
- `clear()` on success path and resume-delete only.

Prevent render loop: write to Storage, not to React state on every Storage write. React state updates only on hydrate and on `clear` / successful replace from resume. While typing, parent `useState` is source of truth; Storage is a mirror.

**Do not** store `data` (catalog) in the draft.

## 4. TerminalApp wiring

After `handleLogin` succeeds (`setEmployee`, `setData`, currently `setScreen("home")`):

1. `readDraft(employee.id)`.
2. If none → home as now.
3. If parse fail → open resume dialog in error mode (delete only).
4. If ok → open resume dialog.

Do not auto-navigate to the operation screen.

Resume dialog props: `draft | parseError`, `onContinue`, `onDelete`.

- Continue: `setScreen(draft.operationType)`, close dialog. Screen hook hydrates independently from the same key (single source = Storage). To avoid flash of empty form: either pass `initialDraft` as prop **or** read synchronously in the screen's first render (`readDraft` is sync). Prefer **sync read in hook initializer** (`useState(() => read...)`) so first paint has picks.
- Delete: `clearDraft`, close, stay home.
- Choosing another tile while a valid draft of a **different** type exists: open the same dialog (continue existing vs delete then `setScreen` requested). Same type: enter screen, hydrate, no dialog.

Idle `logout` unchanged. Cookie delete unchanged. `IDLE_MS` unchanged.

Copy:

- Title: **Есть незавершённая операция**
- Line: `{Тип} · начата {time}` where тип = Торцовка / Присадка / Упаковка / Рабочие часы; time from `createdAt` via `formatDateTime`.
- If `Date.now() - createdAt >= 24h`, second line with age. No auto-delete.
- Buttons: **Продолжить** | **Удалить черновик**
- Delete confirm: **Введённые данные будут потеряны.** [Отмена] [Удалить]
- Error: **Не удалось прочитать черновик.** Only [Удалить черновик].

Use existing terminal button classes (`h-14 rounded-xl text-lg`), `Dialog` like QuantityDialog, `scrollbar-thin-y` if the body can overflow.

## 5. Screen wiring

### 5.1 TORCOVKA

Remove `const requestId = useRef(newRequestId())`.

`const draft = useTerminalDraft({ employeeId: employee.id })`.

Initialize state from `draft.draft` when `operationType==="TORCOVKA"` else defaults.

`clientRequestId: draft.clientRequestId` in both `submitTorcovka` calls.

On `CREATED`: `draft.clear(); requestId rotation is clear()+unmount via onDone`. Do not `newRequestId()` for the next operation until the next screen mount (home then new enter). `onDone` unmounts; next enter is a new hook instance.

On throw: do not clear.

On `ACK_REQUIRED`: set `pendingAck` as now; persist `ackUi.phase` from band (`SUSPICIOUS`→`suspicious`, `EXTREME`→`extreme`); keep same id.

Hydrate `ackUi`: after catalog is available, `computeTorcovkaWasteMetrics`; if saved phase ≠ `none` and current band still SUSPICIOUS/EXTREME, re-open the matching dialog and restore reason/note. If band is now NORMAL, stay on form, keep reason in state but do not show ack.

Stale lot: if `lotId` not in `lots`, keep ids in state, show banner «Пакет больше недоступен», disable confirm.

Do not persist `wasteMetrics`.

### 5.2 PRISADKA / UPAKOVKA

Same hook. Hydrate `picked` Record from `picks[]`. Submit uses `draft.clientRequestId`. Success → `clear()`. Stale: keep qty; if tile missing or `qty > max`, disable confirm + banner, **do not** drop keys.

### 5.3 HOURS

Hydrate `value` from `hoursInput`. Submit `draft.clientRequestId`. Success → `clear()`.

### 5.4 QuantityDialog buffer

Not persisted. Documented limitation in 01.11.

## 6. Stale handling (UI, not server)

No new server endpoints. On confirm, existing `submit*` errors already toast (`Недостаточно реек`, `Пакет реек не найден`, …). Keep draft.

**Owner correction (see top of this file):** current-stock mismatch is a
**warning**, not an unconditional Confirm disable. Same `clientRequestId`
may be an idempotent replay. Server is source of truth. Hard-block only
structurally impossible payloads.

Historical client checks below were the pre-correction plan:

- TORCOVKA: lot in current `data.railLots` with `remainingQuantity > 0` and matching batch; `railsTaken <= remaining`; not `overLength`.
- PRISADKA: each pick still in `buildTiles`; `qty <= pending`.
- UPAKOVKA: product ACTIVE; `qty <= canAssemble`.

These checks **must not** disable Confirm solely because current stock is
lower. They do not `clear()`.
