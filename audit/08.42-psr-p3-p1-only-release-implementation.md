## What this package does

The release executor materializes the 45 historical migration blobs from `678cbc1d` plus the pinned P1 blob, then runs real `prisma migrate deploy` in a separate one-shot container. That container's command is `node` plus the Prisma CLI. It does not execute `docker-entrypoint.sh` and it does not start or replace the application container.

Before a first apply, the executor requires a recovery proof bound to the attempt: archive bytes, a creation-time SHA-256 recomputed from those bytes, restore exit 0, matching migration and logical-schema fingerprints, and matching aggregate counts. The string `RESTORE_VERIFIED` is rejected. An image id is checked as a runtime identity and is reported as `imageGitSha: UNVERIFIED`.

Production container names, the production database name, and the production compose network are refused. `productionReleaseAuthorized()` returns false. `EXECUTION_POLICY.allowProduction` stays false.

A second call after P1 is already applied reads the catalog and does not spawn. An ambiguous or failed spawn writes a marker and is not retried.

`scripts/p1-writer-preflight.sh` is a read-only SQL check. `scripts/deploy.sh` and `scripts/ci-prod-remote.sh` call it before backup and before `git reset`. The new writer deploy refuses when P1 is absent or inconsistent. When P1 matches, this check exits 0 and the existing backup, build, health, and rollback path continues. There is no unconditional global stop and no always-failing workflow.

## Isolated proof

One local run created test-owned PostgreSQL 17 containers, applied the 45 historical migrations, built an application container from the pinned historical `docker-entrypoint.sh` and `package.json`, and started that container with `node /app/health.js`. The running command was not `docker-entrypoint.sh`. A backup of that database was restored into a second disposable PostgreSQL. The one-shot migrator then applied P1. The fresh catalog had 46 successful rows, the pinned checksum, and the P1 column, CHECK, function, and trigger. The application container id, image id, and `StartedAt` were unchanged. Historical `createBatch`, replay, and `updateBatch` from `678cbc1d` then succeeded, with `receiptProvenanceSnapshot` left SQL NULL. A repeat call did not spawn. The writer prerequisite was false before P1 and true after P1.

The application container is not a full Next.js production image. That image's entrypoint is `docker-entrypoint.sh`, which this procedure must not execute. The business operations are the historical modules, run against the same database the one-shot migrated.

## Not authorized

P1 production migration remains **NOT AUTHORIZED / NOT EXECUTED**. A future production run needs a separate explicit Owner authorization. The 2026-10-15 production backup remains diagnostic evidence, not an approved recovery point. The running production image id is not a Git SHA.
