## 3. Original null-product cancellation bug

`applyOzonSupplyCancellation` previously:

1. decided `close` with `restoreQty = deductedQty`;
2. restored ProductStock only when `restoreQty > 0 && supply.productId`;
3. then always reset `deductedQty` / `shortfallQty`, set `status=PENDING`, `stockAccountingOpen=false`.

An open accounted cycle with `deductedQty > 0` and `productId = NULL` could close and erase the accounting watermark without restoring physical ProductStock.

## 4. Fail-closed implementation

After the Supply row is locked and `evaluateOzonSupplyCancellation` returns `close`:

```text
if restoreQty > 0 && supply.productId == null
  throw SUPPLY_CANCEL_PRODUCT_BINDING_REQUIRED
```

This runs **before** ProductStock mutation, watermark reset, `status=PENDING`, `stockAccountingOpen=false`, and caller ChangeLog.

Do not infer product from current SKU. R-04 frozen binding stays frozen. No rebind during cancellation.

Zero-restore remains legal:

```text
stockAccountingOpen = true
deductedQty = 0
shortfallQty > 0
productId = NULL
```

Cancellation closes with `restoreQty = 0`, no ProductStock mutation, no binding requirement.

## 5. Original Supply lock-order defect

`marketplace-sync.ts` previously:

1. looped incoming supplies in provider/API order;
2. `supply.upsert(...)` acquired Supply row/index locks in that order;
3. only later computed deduct/cancel keys;
4. only later called `lockSuppliesInOrder`;
5. `applySupplyDeduction` / `applyOzonSupplyCancellation` acquired ProductStock locks one target at a time.

Explicit sorted Supply locking was therefore **after** some Supply write locks. ProductStock locking was incremental. That is not the accepted global lock plan.

## 6. New request-level lock plan

```text
normalized incoming Supply keys
→ deterministic Supply upsert/write order (marketplace, externalId, sku)
→ pre-lock existing incoming ∪ existing Ozon cancel keys in canonical SupplyKey order
→ upsert incoming in that same order
→ full accounting Supply target set
     SHIPPED/ACCEPTED candidates
     ∪ Ozon cancellation keys
     ∪ same-sync cancellation-wins identities
     (deduplicated, canonical SupplyKey comparator)
→ lock that set in canonical order (reentrant)
→ read locked Supply accounting state
→ capture one transaction-local production_cost_flow decision
→ derive ProductStock targets from locked state + R-04 binding rules
→ lock ProductStock in productId ASC
→ physical deduction/cancellation
→ accounting watermark/status
→ audit ChangeLog (caller)
```

Orchestrator: `runSupplySyncAccounting` in `src/server/internal/supply-deduct.ts`.
Pure plan: `src/server/internal/supply-lock-plan.ts`.

### 6.1 ProductStock target derivation

Union of:

- deduction candidates that can account against a bound product (`resolveSupplyProductBinding`; live rebind only if accounting has not started; frozen `Supply.productId` once started);
- Ozon cancellation candidates with `restoreQty > 0` **and** retained `productId`.

Same-sync Ozon cancellation wins: that identity is excluded from deduction targets; restore uses retained `productId` only. Duplicate productIds collapse. Sort: `productId ASC`.

### 6.2 Missing ProductStock rows / cost-flow

One TX-local `readSupplyCostFlowActive(tx)` is captured **after** Supply locks and **before** ProductStock locks / physical apply. Apply helpers receive that boolean and do not independently re-read the setting (avoids the UPAKOVKA lock/apply split). This is not a process-global cache and is not activation coordination. `ARCH-P1-001` is untouched.

| Mode | Lock | Physical |
| --- | --- | --- |
| INACTIVE (current production) | `createMany` quantity-0 placeholders + `FOR UPDATE ORDER BY productId` | quantity-only deduct/restore unchanged |
| ACTIVE | lock **existing** rows only; never mint uninitialized monetary pools; never call `ensureAndLockActiveProductPools` | positive deduct/restore remain `COST_FLOW_QTY_ONLY_WRITER`; full-shortfall / nonphysical path still accounts |

Apply helpers may re-lock an already globally locked ProductStock row. That cannot invert order because the helper target is a subset of the globally locked set.
