2. Batch remainder write-off. Source `BatchRemainderWriteOff.effectSnapshot`. Causation `BATCH` / write-off id. One `ADJUSTMENT -quantityBefore` per positive `railLotId`.
3. SimplePurchase receipt. Source `SimplePurchase.quantity` and `nomenclatureId`. Causation `SIMPLE_PURCHASE` / `SimplePurchase.id`. One `RECEIPT +quantity` on `NOMENCLATURE`.

Batch receipt, Inventory, Supply, and production submit are not in this slice. There is no UI, route, Server Action, CLI, cron, or scheduler.

`readSlice1InvariantA` (line 580) reads the retained source and SHADOW rows in one `RepeatableRead` transaction and sets `transaction_read_only` (lines 587 and 661). ## 3. Invariant A and Invariant B

Invariant A compares the full semantic set: causation, `effectKey`, kind, stock domain, canonical target, `targetSnapshot`, sign, and `quantityDelta`.

`MATCH_OBSERVED` means those sets are equal. It does **not** prove that a warehouse projection changed.

A nonempty Expected set with zero SHADOW rows is `GATE_UNKNOWN` (lines 502–510). Missing movements are not an automatic `MISMATCH` while preservation of SHADOW evidence is unproven.

Every completed result sets `invariantB` to `NOT_EVALUABLE` (lines 47 and 159). No projection witness is implemented.
